# 自适应检测、小目标与轨迹连续性分析及改进方案（2026-07-30）

## 结论

本轮已经完成自适应 `imgsz` 全局默认、成熟轨迹生命周期修复、逐帧识别诊断和 xqh 全流程原生
MPS 回放。可以确认：

- xqh 对齐 AGL 约 130m，1696 个统计采样帧全部选择 `960`，自适应策略按设计生效；
- 1696/1696 帧有识别诊断，合法 YOLO 框 243887 个、非法几何 0；其中面积不超过
  `4096px²` 的小目标 151874 个；
- 同一成熟 ID 回退候选次数为 0；1766 个完成轨迹的 `pipeline_id + track_id` 全部唯一，终止原因
  完整，33/66 秒统计窗口没有结束图像轨迹；
- 不能宣称“小目标检测准确率”或“轨迹永不丢失”。当前没有外部批准真值，Precision、Recall、
  IDF1、HOTA 和正式 ID switch 均为 `not_evaluated`；同帧检测数与跟踪输出数之比只是工程覆盖信号。

全量数据把问题进一步定位为两个不同层次：稳定悬停阶段的小目标工程覆盖为 45.32%，离场高运动
阶段降到 4.77%。因此生命周期回退问题已修复，但检测后的确认、跨帧关联、相机高运动和
`stride=10` 的时间间隔仍是下一阶段重点。离开画面的目标自然终止也不能被定义为“丢轨”。

| 层级 | 回答的问题 | 当前结果 | 能否表示准确率 |

L1 的分子与分母不是逐检测一一匹配：ByteTrack 的首帧确认、低分二阶段、保留的 lost 轨迹、类别
平滑和离开画面都会改变同帧数量。因此该指标适合发现阶段性异常，不适合直接叫“跟踪率”或
“识别率”。下一阶段先补检测索引到关联结果的 lineage，才能形成严格的工程跟踪留存率。

## 根因树

1. 检测尺寸：已不是当前主故障。adaptive 在对齐高度稳定选择 960，所有统计帧都有检测且非法框
   为 0；但没有真值，仍不知道 YOLO 的实际漏检/误检。
2. 小目标确认：摩托、行人、三轮车的框小且置信度易波动，短暂出现可能留在 ByteTrack 未确认或
   第二阶段，导致同帧输出低。不能通过全局降低阈值掩盖。
3. 跨帧关联：stride 10 使处理间隔约 0.334 秒；离场相机运动叠加目标运动，使小框的 IoU 快速下降。
   现有相机补偿可用但仍需把 warp 质量、归一化位移和实际 `dt` 纳入诊断。
4. 生命周期：33 秒年龄淘汰、地图/地理质量降级造成成熟回候选的问题已修复；当前成熟回候选为 0，
   不是本轮低覆盖的原因。
5. 性能：960 档本次 YOLO p50/p95 为 195.4/1128.8ms，完整管道 p50/p95 为
   9022.3/15656.9ms，不能声明实时性能通过。全局铺开切片或 1280 会进一步增加积压。
6. 数据口径：旧运行有 11 个逐帧数字类别标签，已前向修复；正式识别和身份准确率仍缺外部真值。

## 改进方案

### P0：已完成的正确性底座

| 改进 | 实现边界 | 验证 |
|---|---|---|
| adaptive 全局默认 | 仓库配置、Platform 启动、原生回放一致；固定尺寸仅显式诊断 | 1696 帧全部 960 |
| 生命周期单调 | mature 不因窗口、地图或质量回候选 | 回退 0、完成唯一 |
| 小目标诊断 | 按类别和 `<=4096px²` 分层 | 诊断覆盖 100% |
| 类别目录 | 跟踪器持久 class ID→name，不依赖当前帧 | 类别切换待确认回归 |
| 统一评估器 | 纯函数 + 只读 CLI，分开工程覆盖和正式精度 | 合成测试 + xqh 全量 JSON |

### P1：关联可解释性与小目标连续性

1. 在 `GroundTrajectoryTrackerNode`/`BYTETracker` 增加逐检测关联 lineage：输入 `detection_index`，
   输出 `matched`、`new_unconfirmed`、`low_score_second_stage`、`class_switch_pending`、
   `lost_recovered`、`removed` 等原因。每个检测只能有一个结局，聚合计数必须守恒。
2. 逐帧记录相机 warp 内点率、重投影残差、全局位移，以及检测中心位移/框高。以飞行阶段、目标
   尺寸和实际 `dt` 拆解，而不是只看总量。
3. 使用真实时间步和目标尺度设计软关联代价：小框允许按框高归一化的中心位移，过程噪声随 `dt`
   增长；类别只作业务组软约束。先 shadow 对比，再用同一批检测输入启用，不恢复固定 `dt=1` 的
   Mahalanobis 硬门。
4. 高运动阶段动态提高采样频率（例如 stride 10 降至 5），触发条件来自 warp 质量/位移并带滞回；
   与 adaptive `imgsz` 独立。必须同时满足队列、MPS P95 和 EOF 门禁。
5. 2 秒短漏检继续保留旧 ID；只有显式 association timeout、源时间断点或 EOF 完成。目标已出画时
   正常结束，不纳入“异常丢轨”。

### P2：受预算约束的小目标检测增强

1. 只在高 AGL/小目标密集 ROI 触发高分辨率二次检测或重叠切片，优先 motor、pedestrian、
   tricycle、bicycle；全画面第一遍仍是 canonical 输入。
2. 同帧、同源图像比较 fixed 640、adaptive 960、fixed 1280 和 ROI 二次检测；分别报告每类小目标
   检测数量、关联 lineage、轨迹寿命与 MPS 延迟，不用不同帧样本做横向结论。
3. 只有外部提供批准真值后，才计算类别/尺寸 Precision、Recall 和漏检；模型微调、阈值调整和 NMS
   变更必须基于该真值集。禁止通过全局降低置信度或成熟门槛制造“更高跟踪率”。

### P3：性能与生产化

1. 为 reader/detector/tracker/stats 分别记录队列等待与节点执行时间，分离并发测试或落库积压造成的
   `pipeline_processing_ms` 长尾。
2. 在相同模型、尺寸和输入上评估半精度、批处理/微批、受控跳帧和模型量化；任何优化必须保持
   非法框 0、候选业务泄漏 0、生命周期对齐和完成幂等。
3. 将检测 p50/p95、端到端 P95、publisher drop、Kafka/road9 排空时间纳入生产容量门禁；当前结果
   只能视为本机功能工程验收。

## 验收矩阵

| 门禁 | 基线 | 下一阶段验收 |
|---|---:|---|
| 诊断帧覆盖 / 非法框 | 100% / 0 | 必须保持 100% / 0 |
| mature→candidate / 重复完成 / 缺原因 | 0 / 0 / 0 | 必须全部保持 0 |
| 稳定悬停小目标工程覆盖 | 45.32% | 同检测输入不得下降超过 2 个百分点 |
| 离场小目标工程覆盖 | 4.77% | 同检测输入目标提高至少 20 个百分点，并给出 lineage 原因守恒 |
| 短漏检 ID 连续 | 2 秒窗口已覆盖 | 合格检测链中恢复旧 ID；不得通过延长完成窗口掩盖 |
| 业务隔离 | 候选泄漏 0 | 速度、流量、车道、拥堵、TCC 继续为 0 泄漏 |
| 性能 | YOLO P95 1128.8ms | 新方案不得恶化；生产阈值另行容量评审 |
| Precision/Recall/IDF1/HOTA | `not_evaluated` | 仅批准外部真值到位后启用 |

“离场小目标 +20 个百分点”是同检测输入下的工程改进目标，不是准确率承诺。若 lineage 证明多数
目标已经离开有效画面，应调整有效样本分母并保留原始总量；不得删除困难帧或修改历史证据。

## 发布与回滚

- P1/P2 每项改动独立开关，默认先 shadow；对比必须使用新 `run_id/pipeline_id/topic/output`。
- 代码部署后通过 Platform 生命周期重启检测 Pipeline，旧进程不会热更新。
- 不清理或回写现有 xqh Kafka、road9 和证据；旧产物中的数字类别标签作为历史数据质量事实保留。
- 若稳定悬停覆盖下降、重复完成出现、业务隔离破坏或性能显著退化，关闭对应关联/二次检测开关，
  保留 P0 生命周期和诊断底座。
