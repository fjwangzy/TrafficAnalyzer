# 四进程管道、轨迹传输与事件保真采样（2026-11-03）

本次同时实施传输减负与第四进程隔离。生产入口仍为`main_optimized.py`，原生完整包`2026.11.03.3`默认启用。Mac/MPS默认三进程，检测/业务节点与原有设备选择不变。约1FPS的现场性能问题尚未以本轮真实NPU素材复验，下面结果属于工程验证。

## 进程与所有权

| 进程 | 所有权与输出 |
| --- | --- |
| reader/detector | 原频率读取、检测；原帧共享内存队列默认8 |
| tracker | 完整轨迹和原频率速度、方向、统计、冲突与执法；发送新增点和当前业务事实 |
| show | 独立只读RenderSnapshot，每车最多30个原始尾迹点；绘制、编码、视频/证据文件 |
| egress | 历史片段、冻结事实、几何采样、归档、GeoJSON和Kafka；不接收整张视频帧、不重新投影坐标 |

显示快照去掉完整历史、分类历史、外观图像与质量历史，保留证据所需当前状态。它与在线TrackElement不共享可变对象。tracker→egress只传每个track的新增权威点及帧事实，后者不携带尾迹；egress根据原始点水位恢复有界实时视图。稳定ID、点序号、源时间/帧、原有像素/ENU/GCJ-02和质量信息原样保留。完成计数较短的轨迹也用显式discard结束，不能静默漏掉已传增量。

## 持久确认与退出

两个发送角色各有递增包序号和内容SHA-256。每批最多1024个新增点，归档队列默认32批；writer写入本管道`KAFKA_SPOOL_DIR/<pipeline>/egress/pending.packets`并fsync后才确认。重复相同序号/内容可幂等接收，缺口或内容冲突立即失败。持续满队列或连续10秒无持久确认进展使整管道失败；不丢轨迹增量或关键事件。ACK计时从当前待处理区间开始，并随实际确认前进，模型预热不占用空队列的确认预算。发送端仅在内存保留未确认的不可变线包；队列堵塞、确认失败或worker异常退出时，额外落盘unconfirmed-<role>-*.packets，包含enqueue失败的当前包，避免仅保留writer已收到的部分。若磁盘满导致该保存也失败，明确报告EGRESS_UNCONFIRMED_SAVE_FAILED并保持任务失败，不伪称已保存。

图像进程在绘制前/后分别保存要求的原图与真实输出，传路径、大小和hash。writer验证要求种类、文件和内容后才发布证据消息。EOF同时核对tracker增量、show证据、水位、计数和未匹配事实，任何缺失不得伪造封存成功。关键Kafka排空沿用120秒预算，失败保留spool及incomplete。父进程等待第四进程的最终结果，启动就绪同时要求视频端口和ARCHIVER_READY。

任何worker异常都停止所属管道。Linux reader共享内存用每管道随机nonce前缀；父进程只清理此明确归属前缀，不全局扫描删除其他管道内存。失败退出取消不可完成的队列feeder等待，正常EOF仍完整排空。阶段日志包含BEGIN/WAIT/END、队列深度、确认水位、持久写盘和Kafka发送耗时。

## 完整事实与精简几何

新Replay V2任务先用完整序列生成速度、停车/起步、转向、事件和队列等事实，再生成几何。取消旧完成路径业务计算前的等距抽稀；既有任务和档案不重算。采样`event-faithful/v2`遵守：

- 对每个省略点以同源时间插值校验，ENU≤0.2m、像素≤2px；同时校验源浮点时间与API整数毫秒时间，避免序号拟合或时间量化偏差。
- 普通移动区间≤0.5秒，完整序列已确认的停车事件中段≤2秒；低速蠕行或未知速度仍用0.5秒，不以低于2km/h直接放宽间隔。首尾、语义质量变化、有效坐标/飞行阶段边界强制保留，时间戳/帧号自身不构成质量变化。
- 停车/起步边界、转向、冲突/执法等关键事件前后默认5秒密集保留；长停车中段可稀疏。真实源帧/时间缺口形成断点，不能补观测或跨断点拟合。
- 当前逐帧在线分析继续原频率，不以几何保留比例降低业务采样。

固定Mission UTC时基后冻结完整速度数、总和及三位小数精确频数；按绝对UTC五分钟桶聚合。Platform计算平均值和P85读取这些摘要，不按保留点重算。没有有效ENU的点不冻结有效世界速度。摘要复用现有sampling JSON，没有DDL和新依赖；公共回放API过滤内部频数。v2缺失、矛盾或时基不匹配的摘要拒绝处理，不能回退旧稀疏算法。

密集关键窗口可能超过Kafka单消息预算，因此对大点数组使用可选确定性gzip-json/v1：限制编码/解压大小并携带点数、明文SHA；Platform恢复逻辑points后照常校验，消息身份哈希仍按收到的原始信封。重试复用固定封存信封、traceID、摘要和时间。只有封存、校验及关键持久发送/排空成功才清理本任务临时全量片段；旧档案、失败journal和未完成片段保留。

## 启停与数据版本

原生首次/后续命令见`NATIVE_DEPLOYMENT_2026.11.03.3.md`。新任务默认`PIPELINE_EGRESS_ENABLED=true`、`HISTORY_SAMPLING_ENABLED=true`。可对后续任务关闭几何采样，仍由四进程产生v2完整事实/摘要和全量几何。关闭采样不是将已有v2任务改成旧格式。

首次实际开始v2归档写入archive根`sampling-v2.active`契约标记，并冻结Mission采样配置。rollback/启动入口遇到该标记时拒绝不支持v2摘要的旧消费者；不能直接回到.1/.2。现场所有写入消费者需保持摘要兼容。依赖及两套迁移head门禁不变，普通start不迁移，独立init-db才迁移。Kafka异常后优先最新数据的既定规则保持，不自动回补已跳过区间。
