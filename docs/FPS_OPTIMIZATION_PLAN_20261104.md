# 四进程FPS优化方案（2026-11-04）

状态：P1与P2位置门控子阶段已完成源码及本机验证，完整生产基线、其余P2及现场A/B待完成；未发布新包。实测范围与限制见[FPS_OPTIMIZATION_LOCAL_VALIDATION_20261104.md](FPS_OPTIMIZATION_LOCAL_VALIDATION_20261104.md)。配套[FPS测试与验收方案](FPS_OPTIMIZATION_TEST_PLAN_20261104.md)。本文按2026.11.04.1生产诊断规划，阶段耗时目标与FPS范围均为待验证目标。

## 1. 基线与目标

当前pipe-8f75642b完成水位显示272帧/180.623秒=1.506 FPS，末个约30秒窗口1.363 FPS。捕获线程允许0–95核、所示CPU配额不限；第四进程确认持续前进，无持续积压。第二进程为当前主要限速点。完整依据见[NATIVE_FPS_DIAGNOSIS_20261104.md](NATIVE_FPS_DIAGNOSIS_20261104.md)。

| 环节 | 捕获墙钟中位数 | 初步目标 | 说明 |
| --- | ---: | ---: | --- |
| P2增量/快照/序列化边界 | 188.8ms | 40–80ms | 第一轮；必须先分解才能确认收益来源 |
| P2关联整体 | 143.9ms | 80–110ms | 第二轮；门控是内部子阶段 |
| P2轨迹状态、速度 | 各60.6/38.4ms | 各25–40/20–25ms | 第二轮；目标区间非同一帧预算 |
| P2冲突 | 82.55ms | 45–65ms | 第二轮；先确认候选构造/几何计算占比 |
| P3绘制、编码 | 各187.85/39.9ms | 条件进入第三轮 | 第二进程改善后重新排序瓶颈 |

首轮争取约1.7–2.0 FPS，第二轮累计争取约2–3 FPS。现有约三分钟尾部不是受控A/B基线，不能仅与1.506做比值宣称提升。实施前须补相同输入、相同负载的基线；真实结果不达标时如实记录。

同一次P2处理跨度约693ms，其中egress_delta为208.4ms。只把该次208.4ms完全消除，示意上限也仅为1/(0.693−0.2084)≈2.06 FPS；它不是稳定理论上限或其他帧的预测。达到2–3 FPS需要P2实际每帧服务时间约333–500ms，不能仅靠移除一次复制。不同阶段独立采样中位数不相加，嵌套阶段不重复计时。

## 2. 约束

- 生产仍以main_optimized.py为唯一入口，四个worker分工不变；Mac/MPS仍默认三worker。
- 保持模型/OM哈希、输入尺寸及adaptive规则、stride、阈值、遥测、源时间和在线业务计算频率。保持生产路网开关现状；不通过关闭冲突、减少目标或过滤有效数据提FPS。
- P2保持权威完整状态与原有计算语义；新增点、业务事实和关键事件不静默丢弃。原帧队列8、归档队列32批、每批最多1024点、持久ACK、10秒停滞失败、双EOF、120秒关键发送排空保持。
- 轨迹采样仍为event-faithful/v2，ENU0.2m/像素2px、普通/未知或未确认停车0.5秒、确认停车中段2秒、关键窗口前后5秒；完整速度分布与统计摘要不由显示/稀疏几何重算。
- 不新增运行依赖和DDL，不修改系统Python、全局动态库或CPU亲和，不盲目增加数值库线程。
- 认证、迁移head、模型、消息身份/哈希、质量与证据门禁保持。Kafka消费异常“最新数据优先”不变。

## 3. P0：建立可复现基线

交付物：固定输入manifest、P2确定性回放驱动、显示固定帧驱动、阶段剖析结果及原版输出基准。当前已实现传输与门控子路径基准，完整固定检测/遥测P2回放及业务差分驱动仍待实施，不能将子路径合成状态基准视为全部现场负载已复现。

固定并记录原视频/SRT/模型/配置哈希、软件版本、输入尺寸与adaptive决策、stride、遥测offset、CPU/cgroup、NPU与驱动信息。从同源检测结果和遥测记录重放P2，避免检测浮点或实时取帧差异遮盖优化效果。至少覆盖生产约250–300活动目标及轨迹增长过程。

细分P2：增量提取/规范化、显示视图、归档事实、pickle、ACK排空、队列put；关联：测量数组、预测/投影、距离/门控、指派、状态/历史维护；状态与速度：分类投票、历史整理、逐目标投影/质量组织、外观裁剪/编码、拟合/EMA；冲突：候选枚举、必要条件、几何/TTC/PET、事件更新。

帧级服务时间使用单调时钟，带pipeline/frame/source_time与目标数、历史点数、候选对数、两路载荷字节。热点函数结合CPU采样栈判断；process_time包含同进程其他线程，细分时尽量另记当前线程CPU。分项计时互斥并报告未归属时间；低频聚合与有界采样，测量开销目标不超过3%，否则先降低采样频率。日志写盘不放进每目标热循环。

准入：同一输入能重复产生现场同类CPU热点，并能检测载荷/历史增长回归；原版输出稳定。不能复现时先记录差异和补证据，不直接按猜测重写业务算法。

## 4. P1：减少P2的数据交接成本

涉及services/PipelineEgress.py、elements/RenderSnapshot.py与FrameElement.py；main_optimized.py只接线，不放算法。

1. 根据ShowNode、EgressEvidenceNode、KafkaProducerNode等实际读取字段列出白名单。显示视图保留当前绘制身份、标签、道路/质量显示所需状态和最多30个原始/补偿像素尾迹；完整历史、分类历史、外观裁剪不进入显示队列。证据、annotation、共享内存和事件上下文逐项列入契约，不能因“精简”丢掉。
2. 四进程P3采用专用显示视图。可复用现有三进程display_only思路，但必须补四进程证据/元数据测试，不能仅切一个参数视为完成。
3. 归档事实独立构建，不经由“创建一份通用FrameElement再删除字段”的路径。发送必要当前事实、水位/点数与身份；历史/有界统计尾部由D按原水位恢复，不重新投影。候选轨迹、质量与飞行阶段所需信息由消费依赖决定，不能一刀切删除所有世界坐标或候选信息。
4. 每份数据在边界只规范化一次；同一帧在两个视图间可共享已冻结的不可变小对象，不能共享P2仍会修改的list/dict。仅序列化未确认批次一次，并复用重试的原始字节/hash。保留失败时未确认包落盘。
5. 不把完整TrackElement/历史再次藏入其他字段；不以增大队列掩盖慢处理。先优化复制与编码，再决定是否需要仅针对可重建预览的合并，轨迹/事实/事件禁止合并丢失。

完成：采样与画像证明P2数据交接显著下降；250车×500/5000点时显示载荷不随历史线性增长；所有业务、画面/证据、ACK/EOF故障门禁通过。40–80ms是目标，不是仅靠字段数量推算的结果。

## 5. P2：关联、状态、速度和冲突优化

每个子项独立提交/开关评估，先测后改，通过结果对照后才进入下一项。拟在configs/app_config.yaml配置各子项开关，按新任务固定并记录配置摘要，不在活动Mission中途切换。关闭某项只恢复同一兼容版本的原计算路径，不改变v2数据协议、抽帧或业务功能；当前尚未添加这些开关。

### 5.1 关联

检查byte_tracker/utils/matching.py、kalman_filter.py、byte_tracker_model.py及GroundTrajectoryTrackerNode。每帧一次构造检测测量/框数组，复用只读结果；按相同数学定义批量处理投影/门控，减少逐行小矩阵调度和Python对象转换。维持chi-square阈值、only_position、协方差、inf掩码、匹配阶段顺序及确定性tie行为；不得按shadow名称关闭门控。

当前shadow_gate约36ms，属于约144ms关联总耗时，剩余成本仍须画像。批量门控若在近阈值/病态矩阵上改变匹配，回到原实现或保留针对该数值条件的原路径，不改阈值“补偿”误差。

### 5.2 轨迹状态与速度

检查TrackerInfoUpdateNode、SpeedEstimationNode。分类投票按原有有界窗口增量维护计数，正确移出旧观测、删除零计数，并保持并列票决策顺序；不能未经画像就宣称现有有界历史是无界扫描。帧级重复分类配置/矩阵/时间转换可缓存，缓存键须包含影响结果的参数及版本。

速度保持当前历史窗、有效世界坐标选择、回归/稳健规则、EMA顺序及无ENU时的null语义。优先减少数组重复构造；只有逐步差分通过后才采用批量拟合或递推量。递推算法处理长序列误差漂移、窗口移出和缺口重置，不能仅比较短期平均值。

### 5.3 冲突

检查ConflictDetectionNode的真实热点后决定是否构建保守候选索引或批量几何运算。候选过滤必须是原规则的必要条件，候选集合应覆盖原逻辑所有可能有效对，并对原版实际事件做到零漏检；不以启发式距离、车道或地图质量排除目标。无可证明的有限边界时保留原枚举。

逐帧保持事件参与者、风险值、TTC/PET、首发/持续/结束时间与证据上下文，事件状态机顺序不变。缓存跨帧使用需验证速度/轨迹/质量变化失效条件，不能沿用已过期候选集。

## 6. P3：显示优化的进入条件

第二轮后若P3服务时间接近/超过P2或显示队列持续回压，再优化ShowNode的批量坐标变换、尾迹分段与绘图对象创建，随后评估编码。当前绘制约188ms、编码约40ms，二者若同帧相近，P3约4 FPS量级的能力只是粗估，不能当作已测得固定上限。超过4 FPS需要重新测量整条管道；不提前承诺。

画面分辨率、显示30点、成熟/候选样式、视觉补偿、文字、冲突余辉和证据内容保持。性能叠字可单独对照，不能降低证据质量或丢帧来宣称处理吞吐提高。
