# 无人机换道与交通执法检测算法实施方案

日期：2026-09-07。修订：按用户要求，原始轨迹线是换道判定主输入，车道几何完全可选。状态：算法设计建议，尚未实施、训练或验收。本方案核对当前代码和 `req/智能体和智算模型部分-无人机.docx`，说明如何补齐视频端行为检测与平台事件闭环；不改变现有运行契约或将设计指标记为实测结果。

建议沿用 YOLO11、纯图像 ByteTrack、逐帧世界投影和现有 Platform，新增换道、执法事实两个业务节点。第一阶段采用轨迹形态与运动学状态机，优先稳定悬停片段，不依赖车道地图；第二阶段提升货车外观识别、覆盖巡航；需求明确写出的 LSTM 加卡尔曼预测单独建设和对比验收。算法输出保持 AI 待复核线索。

当前接缝检查结果：

- `RoadMapMatchingNode.process()` 在调用 `_match()` 前执行 `_clear_road_fields()`，随后传入的 `track.matched_lane_key` 已为空；上一车道连续性奖励及转移约束实际失去输入。这是已有地图匹配的独立问题。仅在完善可选车道解释时处理并增加回归，不作为轨迹换道算法的前置条件。

## 二 共用时空和质量基础

1. 图像关联继续在 H、ENU 和地图处理之前完成。地图缺失、变更或质量下降只影响新事件资格，绝不拆分或结束车辆 ID。
2. 基础检测使用映射到同一局部参考帧的像素轨迹；有可信逐帧地理投影时可采用固定锚点 ENU 轨迹并输出米制量，两者均不要求车道几何。不可在同一候选窗口中混用像素与 ENU。需求中的 GCG02 按项目既有 GCJ-02 命名处理；经纬度角度值不直接用于米制计算。
3. 每个窗口使用源视频时间和真实 `dt`；同时记录带时区的业务时间与处理时间。离线回放的限行时段按原始采集时间求值，不按回放电脑时间求值；原始绝对时间缺失则不能判断时段规则。
4. 门禁分为轨迹连续性、地理投影质量、地图/围栏质量、类别质量和规则可用性。每类事件只依赖所需门禁：轨迹换道仅要求连续可靠轨迹和可用运动补偿；米制速度要求地理尺度；区域事件需要围栏但不必具备完整 Lane/Link。
5. 基础换道不得以 `road_analytics_eligible`、`matched_lane_key` 或地图版本作门禁。只有附加跨边界/线型解释才检查地图配准误差；`map_match_confidence` 不是标定后的概率。
6. 使用当前连续有效地理点，不能把历史最后一个非空 GCJ-02 点当作本帧位置。轨迹参考系重置或补偿失效时结束受影响窗口并记录原因，保留图像 ID。可选地图版本变化仅影响地图解释，不得终止基础换道候选；规则变化只分段对应规则事实。

无人机俯视车辆框不直接等于地面占用轮廓。第一阶段以一致的车辆轨迹代表点判断轨迹横移行为；明显斜视、框抖动或车顶高度偏差过大的样本降级。后续 OBB/实例分割可以改善轮廓，但其四角投影仍需处理车高与视差，不能直接称为轮胎压线证据。

## 三 原始轨迹线驱动的换道识别算法

### 1 输入与无人机运动消除

基础输入为 `track_id + trajectory_points + trajectory_timestamps_sec + trajectory_frame_nums`，辅以检测置信度、真实观测/预测标记和背景运动估计。可选输入为逐点 ENU、历史目标尺度、同向邻车轨迹和车道几何。`lane_history` 与 `current_lane` 不参与基础判定。

原始像素轨迹是跨相机帧累积的点列；跟踪器已经使用相机补偿，不等于存下来的历史轨迹点已处于同一参考坐标系。需根据 `camera_motion_warp` 的实际方向，把窗口内每个历史点映射到同一局部参考帧，并验证正逆变换；保留源点，不覆盖原始轨迹。复用现有背景 LK/RANSAC，不重复补偿已经处于固定 ENU 的点列。

采用有界短窗和局部参考帧，避免全视频累计变换漂移。背景特征不足、强视差或大幅转镜导致补偿不可信时记录不可判定；不会因没有地图而停用算法。有可靠 ENU 时可运行米制轨迹分支，但不能让地理缺失阻断可信的稳像轨迹分支。

### 2 从自身历史轨迹建立方向基线

在车辆稳定前进的短窗内，按真实时间拟合 `p(t) = p0 + v0(t-t0)`，得到有向前进单位向量 `e = v0 / |v0|`，以时间顺序消除 PCA 类轴向拟合的正负歧义。短轨迹、静止或方向不稳定时继续积累，不强行判断。

取左法向量 `n`，将稳像轨迹转换为车辆自身局部坐标：

```text
s(t) = dot(p(t) - p0, e)       # 相对初始前进方向的纵向位移
d(t) = dot(p(t) - p0, n)       # 相对初始轨迹延长线的横向位移
v_lat(t) = d 的短窗拟合斜率
delta_heading(t) = 当前运动方向相对 e 的夹角
```

图像 y 轴向下，必须转换为一致的右手坐标后定义左右，否则左右标签会反转。候选行为开始后冻结该局部参考系，不能每帧重定向从而把横移吸收掉；处理结束后才更新稳定基线。

有 ENU 输出米制横移；只有图像时输出稳像像素与归一化横移 `D = Δd / w_ref`。`w_ref` 可由候选前窗目标框沿横向的稳健尺度近似，不把旋转 AABB 宽度当作真实车宽。现有 TrackElement 只有当前框，若采用尺度归一化，节点需增加有界逐时刻尺度缓存。全过程固定参考尺度，避免框尺寸变化制造虚假横移。大幅透视变化或尺度不可信时只保留像素量和降级原因。

### 3 判定轨迹是否呈现一次换道形态

典型形态为：前段稳定前进，中段向一侧横移，后段恢复近似原方向并保持新的横向位置。轨迹常呈平缓 S 形，但不要求出现视觉上明显的 S，也不以固定曲率符号序列作硬门槛。

```text
稳定前进 → 持续横移 → 横移减弱 → 新偏移上稳定前进 → 输出一次换道行为
               ↘ 回到原基线：横摆/避让，取消完成候选
               ↘ 持续改变航向：转弯或未完成，另行分类
               ↘ 观测缺口/补偿失败/EOF：未完成，不补造事件
```

联合检查以下证据：

- 前后有足够观测时长且航向基本一致，候选期间总体纵向前进。
- 净横向位移显著超过稳像和检测抖动尺度，且在结束窗中保持，没有马上回到原轨迹。
- 中间阶段存在持续同侧横向速度；结束阶段横向速度回落。允许正常微调，不要求每个点严格单调。
- 行为时长、横向加速度和轨迹曲率合理，排除单帧位置跳变；低速时不依赖不稳定航向和曲率。
- 同一连续图像轨迹提供实际观测证据，不能把完全靠卡尔曼预测补出的横移当作事件。

初始实验参数：前后稳定窗各 0.5–1.0 秒，前后航向差约 10–15 度，归一化横移门槛可从 0.8–1.5 个参考目标横向尺度开始搜索，并叠加大于背景/检测残差的门槛。这些是试验起点，不是现场已验证指标；货车宽度、透视和缓慢换道需要分层调参。允许缺测必须与实际采样间隔匹配，所有计时使用源时间。

输出 `start_time` 为离开稳定轨迹状态的估计时刻，`end_time` 为横移后稳定确认时刻，另保留横向速度峰值的 `peak_time`。无车道几何时不存在可观测的车道线跨越时刻，`crossing_time` 为空，不能用轨迹中点冒充跨线时间。

### 4 弯道与避障歧义处理

仅一条轨迹时，普通转弯通常表现为前后航向持续改变；短暂避让后返回表现为净横移接近零，两者可由上述条件排除。但 S 弯、道路横向平移和避障后保持新位置可能与换道产生相同轨迹，单靠自身点列无法保证区分。

用附近同向车辆的已观测轨迹作为可选增强：先按空间邻近、时间重叠和前进方向筛选，再比较沿途共同弯曲与横移；若多车均呈相同变化，降低该目标独立换道置信度。使用稳健统计而非直接平均，不把邻车同时换道解释为相机运动。没有合格邻车仍能运行基础检测，只保留轨迹语义歧义。该增强不生成车道几何，也不是运行前提。

输出区分 `event_type=lane_change` 的轨迹行为识别与 `lane_crossing_verified` 的车道跨越验证；基础结果带 `inference_basis=trajectory_only`。证据不能排除转弯/避障时保留横向机动候选和原因，不武断升级高置信换道。分数先作为可解释规则分数，不冒充经标定概率。

### 5 可选车道信息与输出

车道几何仅在基础行为输出后丰富结果：补充 `from_lane/to_lane`、线型、跨线位置和适用规则。无图、匹配失败或 AutoLane 编号变化不影响基础换道事件；这些可选字段保持空值。地图证据若与轨迹形态冲突，保留冲突事实及质量原因，不篡改原始轨迹。

最小输出：Mission、SourceProfile、Pipeline、track ID、左右方向、起止/峰值源时刻、前后航向差、横移值及单位、归一化幅度、曲率/横向运动摘要、参考帧与补偿方法、模型/算法版本、质量原因和证据。米制位置和车道字段均可空。没有地图不能确定跨了几条车道，一段连续横移先输出一次行为；若中间恢复稳定再发生横移，可以形成第二次行为。

换道行为不等于违规换道；只有可选边界/规则资料充分时才追加压线等线索，无资料不推导实线、车道编号或许可情况。

### 6 与冲突和预测衔接

从轨迹估计的相对位置和速度中筛选横移侧的邻近车辆，检查未来时刻的轨迹交汇和占用重叠，不要求已知目标车道。使用已有距离筛选或网格限制配对，避免全目标两两组合。

具有可信 ENU 与尺度时计算米制距离、净间距与风险；像素分支只提供图像空间接近提示，不能输出伪造米制 TTC/PET 结论。同向追近可使用净间距除以正闭合速度的简化 TTC；交叉/横移风险需基于相同未来时刻的预测占用。现有正式机非 `path_intersection` TCC 和 CPA 默认关闭口径保持不变，并线风险用独立方法标识和事件契约接入。

预测可在横移候选阶段产生，换道完成事件需等待后段稳定。预测到达时间差与双方实际通过同一区域后的实测 PET 分开记录。

需求指定的 LSTM 与时序卡尔曼融合仍为后续交付项：输入改为车辆自身局部轨迹坐标、速度/加速度、邻车关系、观测掩码和真实 `dt`，车道特征可缺省；卡尔曼负责状态滤波，LSTM 预测未来 3–5 秒多步轨迹。先与恒速/恒加速度基线比较 ADE/FDE、风险误报和延迟，并检查物理约束。无批准数据和对比验收则保持未完成，不用基线冒充网络交付。

## 四 交通执法检测算法

### 1 货车识别

先核对实际加载权重的类别名称和版本，不按配置注释或固定数字强判 truck。复用 YOLO11 的货车候选和现有轨迹类别投票模式，在合格清晰帧上做时序置信聚合；不把业务 `motor` 类别当作货车类别。unknown 和低质量目标不升级为货车。

第一阶段保持 `truck/non_truck/unknown` 契约。针对高空小货车与 van、bus 易混淆问题，第二阶段使用清晰的目标裁剪做补充分类，或微调既有 YOLO11；先评估现有模型，再决定哪条路径有收益。困难样本覆盖厢式货车、皮卡、面包车、公交、专项车辆、遮挡及不同高度，按地点/飞行批次划分训练测试，不能将相邻帧随机分到两边。

需求要求的重/中/轻型、专项车辆列为单独细分类候选与数据验收项，必要时扩展契约，不能伪装成当前三分类已支持。核定载质量、登记类型、通行证和豁免身份不能从车顶外观可靠推导；缺权威数据时返回对应条件未知。

小目标专用损失函数是需求中的技术路径，需通过标准损失与候选损失消融证明收益；不能只增加配置名便声称实现。第二模型和切片推理仅按候选目标、清晰度和性能预算触发，不默认对每帧全图重复推理。

### 2 统一空间规则

沿用 Platform 已有围栏与规则管理。任务启动时冻结区域、规则、有效期、时区、车型条件、豁免条件和来源快照，在检测进程中求值；规则不在每个目标每帧远程查询。缺关键条件采用 `unknown`，不要把未知当作满足。

区域入侵使用内外缓冲与时间滞回消除边缘抖动：先稳定在外、后稳定进入可靠内部才确认进入。视频首帧已经在区域内时记录“区域内观测”，不能伪造进入时刻。所有条件按事件所用版本留证，本地候选规则始终保留 `unverified`。

| 场景 | 检测方法 | 必要排除与降级 |
| --- | --- | --- |
| 货车限行 | 可信 truck 分类 + 区域内/进入事实 + 生效时段 + 车型条件 | 核载、通行证或豁免不明时保留未知，只输出可证实条件 |
| 超速候选 | 对 ENU 位置与真实源时间做短窗速度拟合；在适用限速条件下持续越阈 | 不用轨迹历史最大速度触发；投影跳变、缺测、限速来源缺失则不作超速判断 |
| 禁停候选 | 禁停区内 + 持续低速 + 地面位移半径小 + 连续可见 | 排队、红灯停车、拥堵、临时停车例外；缺上下文时保留停车事实、原因未知 |
| 区域滞留 | 合格区域内观测累计超过阈值 | 滞留可以缓慢移动，与停车独立；中断期间不能累积确认停留时长 |
| 消防通道/其他占道 | 车辆代表点进入或可信占用轮廓与区域相交，持续满足阈值 | 点进入与面积占用分不同方法；拥堵、边界误差及区域身份缺失需降级 |
| 施工区域违规通行 | 生效管制区进入/穿越 + 方向和时段规则 + 豁免条件 | 经批准施工车辆身份未知时不能判为无许可；复用区域通行事实，不建独立大模型 |

车型限速只取有来源、适用道路和时段的规则，不按“货车通常更慢”固定下调。存在经过验证的不确定度 `u_v` 时，可用 `v_est - u_v > configured_limit` 且持续满足作为保守候选条件；没有经验证误差界时只提供速度观测及质量说明。

### 3 雷达融合

现阶段没有真实雷达输入时继续为空。接入后先完成时间同步、外参、雷达观测方向和目标关联；雷达径向速度必须转换为与视频可比的地面速度分量。只有双方测量同一物理量、关联唯一且误差模型有效时才融合，保留视频原值、雷达原值及方法。

独立无偏误差假设成立时可以采用逆方差加权；不成立时保留分源结果或使用已验证的联合模型，不能简单平均。融合异常、设备状态异常、关联歧义分别记原因；不把视频值填进雷达字段。

### 4 连续观测和事件去重

停车与滞留按持续有效观测时间累计，缺测不计时；短缺测可保留待续候选，但输出观测覆盖率和缺口，长缺测结束候选。对象重新出现而 ID 不同时，不以位置邻近强行拼接此前停车时长。

同一 Mission、track、规则版本和连续行为段只生成一次事实。再次离开并重新进入可以形成新事件。超过阈值即可输出达到门槛的已知事实，不必等对象离开；后续证据补全与结束时刻通过明确版本机制管理。EOF 只收尾现有事实，不推测缺失后半段。

## 五 管道与平台落地

拟增加 `LaneChangeDetectionNode` 和 `EnforcementDetectionNode`，业务计算放在进程 2。基础换道节点放在轨迹更新后、道路匹配前，明确不读取正式车道匹配字段。道路匹配后可为事件补充可选车道解释；执法事实节点在统计和 Kafka 输出前运行。必要时新增小型纯几何函数，复用现有 NumPy、Shapely 和轨迹工具，不另建模型服务或规则微服务。

```text
现有检测 → 图像跟踪 → 逐帧地理投影 → 速度/方向/轨迹
  → 轨迹换道节点（无需地图）
  → RoadMapMatching / 现有车道分析（可选丰富，不控制换道输出）
  → 执法事实节点 → 现有冲突/统计/输出
  → 受管证据落盘与核验 → 事件可靠投递 → Platform → road9 → Console2
```

这是一份目标顺序，实施时须保持既有 EOF 和三进程生命周期。共享字段显式声明在 `FrameElement`；节点按 track 保存有界时间窗口并及时清理。配置进入 `configs/app_config.yaml`，Mac 保持原生 arm64/MPS。

事件与证据不放进可截断的 `active_trajectories` 快照，也不将图片字节塞入 Kafka。扩展现有消息封装/可靠发布路径，建议采用独立 `uav_` 事件契约，具体 Topic、msg_type、schema 在实施时成对冻结生产者与消费者；不要把执法消息伪装成旧 `uav_conflict`。Replay V2 任务须同步支持事件类型、源 `offset_ms`、Mission seal、重放与幂等，避免仅改旧消费者而当前运行态收不到消息。

执法存储复用 `uav_ai_events` 主记录及 `uav_enforcement_clues` 详情，证据复用 `uav_evidence_*`，不复制投递/复核状态机。新增消费者需处理 inbox 与线索写入事务边界；不能在外层消费事务内盲调一个另开 session 并提交的 `ingest_clue()`，否则 offset、inbox 与业务事实可能不一致。

证据包应包含原始视频引用、前中后关键帧或短片、轨迹点及源帧索引、遥测/标定、地图与规则快照、模型版本、命中条件、排除结果和哈希。画面叠加交给 ShowNode，判定不能放入 ShowNode。复用现有受管保存和后置发布模式；证据未写完不得先标完整。

事件前后各 3–5 秒可作为实验取证窗口。优先引用原始文件片段或既有编码缓存，不保存无界 4K 原始帧数组；实时断流/EOF 缺失后段时明确证据缺口。无可用原始录像不能伪造 clip。外部发布/投递仍遵守现有 blocked 边界。

## 六 数据和验收

### 工程验收

最小自动化用例覆盖：无地图正常左右横移换道、检测抖动不触发、普通弯道排除、S 弯/避让歧义降级、纯相机平移/旋转/缩放不触发、相机运动叠加真实横移仍识别、观测缺口、地图缺失/版本切换不影响基础输出、EOF 未完成事件、同一事件重试不重复、truck/unknown 分离、候选时段时区、排队与禁停区分、雷达缺失与歧义、证据实物不匹配拒绝完整状态。

真实回放选择现有 XQH 和崇华路轨迹片段，换道必须覆盖完全不提供地图的正常运行；区域执法另选具备相应围栏的片段。补偿失败测明确降级，不将地图缺失当成基础换道失败。对账检测日志、事件消息、road9、证据对象和 Console2，确认不是验证脚本直接注入的样例。既有 TCC、图像跟踪与地图独立性必须继续通过回归。

性能同时测有效观测 FPS、最大观测间隔、节点增量耗时、端到端 p50/p95、Kafka 积压和内存。稳定确认窗口本身会引入检测延迟；处理开销与业务等待时间分开报告。5–10 Hz 可作为换道初始观测目标，但应按现场横移速度验证；现有高空 1280 档曾未过性能门，不能承诺在原硬件加算法后自然达到秒级实时。

### 算法效果验收

没有批准真值时，真实场景准确率/召回率以及 IDF1、HOTA、正式 ID switch、位置 RMSE、速度 MAE 均为 `not_evaluated`；轨迹寿命或看起来平滑不代替精度。遵守项目边界，不建设巡航人工轨迹标注、AI 预标注或轨迹复核工作包。

有外部批准事件/测量真值后，换道评估事件级 Precision/Recall、方向正确率、时间误差和可选地图解释正确率及每视频小时误报数；执法逐类评估 Precision/Recall、每小时误报数、未知率、证据完整率与输出延迟。事件匹配须预先固定一对一时空匹配规则，不能靠运行时 track ID 直接匹配外部真值。按悬停/巡航、高度、光照、密度、遮挡和地图质量分层报告，同时报告系统可判定覆盖率，防止通过大量拒识虚增精度。

货车训练可以使用有许可的公开检测数据及外部提供的本地车型框标签，不扩展为巡航轨迹标注工程。highD 可提供公开换道轨迹研究基线，VisDrone 可用于无人机目标检测训练；二者均不能替代本项目城市路口、飞行运动和执法规则的验收。LSTM 先用获准外部轨迹数据开展对比，数据域不匹配时不宣称现场效果。

## 七 分阶段交付

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| P0 轨迹基础 | 核对原始轨迹点、源时间与补偿方向；实现有界稳像轨迹和自身方向基线；核实证据/消费事务接缝 | 无车道几何可独立运行，纯镜头运动被排除，源点不被覆盖 |
| P1 换道闭环 | 轨迹形态/运动状态机、邻车可选消歧、起止、证据、Replay 与平台显示 | 无地图正负场景和真实轨迹回放贯通，重试不重复；歧义与未评价精度明确 |
| P2 执法闭环 | truck 候选、限行区域、速度、禁停、滞留、消防/施工区域规则 | 六类场景均能输出可证实事实或明确未知，工作台可查真实检测证据 |
| P3 模型与巡航 | 货车细分类/小目标损失消融、LSTM+卡尔曼、并线风险、真实雷达接入 | 分项数据与对比评估完成，性能和覆盖率达到经确认的试点目标；缺外部输入的项单独保持未完成 |

首个最小可用版本建议做“悬停轨迹线驱动的换道识别（无地图可运行）+ 候选禁停/滞留 + 货车围栏线索”。围栏是区域执法的规则输入，不是基础换道所需的车道几何。随后完成速度、占道和施工通行，最后增加细分类、LSTM、雷达和巡航适配。这样尽早得到真实事件闭环，同时保留完整需求的未完成清单。
