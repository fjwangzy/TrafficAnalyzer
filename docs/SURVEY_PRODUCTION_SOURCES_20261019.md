# 2026-10-19 生产测绘来源路径与失效状态修复

用户确认生产素材已放入ASSET_ROOT/videos，检测视频可以播放；现场截图/错误码和生产主机未直接读取。
检查代码发现两处可复现缺陷，不能据本机测试宣称现场所有来源已经恢复。

## 修复范围

1. 生产来源目录使用`/app/test_videos/...`绝对路径，而测绘导入仅移除相对`test_videos/`前缀，
   随后被“只允许相对素材key”的安全边界拒绝。现在只把已登记来源的这两个固定目录前缀转为相对key，
   再由原有survey_asset_roots白名单解析。MP4、SRT/DJI JSON/TXT及从事件建立测绘使用同一规则；
   原始大文件继续零复制引用，不暴露或保存容器绝对路径作为证据key。
2. 首次初始化时若素材尚未挂入，来源会被存为invalid。旧seed只给新记录赋校验状态，旧列表又只读缓存，
   素材后来补齐也不会恢复。现在seed重新校验已有来源但不覆盖现场路径、配置或enabled；
   `/sources`列表对启用的本地invalid/unknown来源在线重检，变化时保存校验结果和时间。
   JSON检查在线程中运行，避免占用API事件循环；状态未变化不反复提交。

已知遥测缺口`known_degradation`仍保持degraded；禁用来源不被列表自动启用。
路径越界、任意绝对路径、缺失素材和非法JSON仍拒绝，不以强制valid代替检查。

## 验证

- 修复前，生产绝对路径导入及旧invalid状态恢复的3项用例失败；修复后通过。
- 路径覆盖相对key、test_videos相对前缀、生产绝对前缀及3种越界/非法路径；证据key保持相对。
- 来源状态覆盖素材晚到、缺失保持invalid、已知缺口保留degraded、禁用保持禁用，
  seed重检保留现场自定义路径/配置和禁用开关。

- 未改动数据库结构、前端布局、地图供应商、检测器或质量门禁；未重跑生产素材/现场容器。
