# 2026-10-19 生产首页登记视频图标常驻修复

## 原因

生产ROAD_FEATURES_ENABLED=false关闭路网态势读取，纯净业务库也没有本机已有的RoadContext坐标快照。
首页原来将非运行中的视频源定位完全依赖于路口地图坐标，没有路口坐标就过滤掉图标。
检测启动后实时遥测提供位置，图标出现；结束/刷新后实时数据不再可用，图标又消失。
该差异可由本机已有路口快照掩盖，与MineMap图标绘制接口无关。

## 修复

- `/sources`为启用且valid/degraded的本地来源增加可空recording_position：从原有SRT/DJI JSON/TXT读取器中，
  取时间不早于视频同步offset的第一条合法GPS位置，按现有工具一次转换到GCJ-02，并附source_time_sec及recorded_at。
- 文件读取继续使用UAV_LOCAL_ASSET_ROOTS白名单；缺文件、非法数据或无有效GPS时返回空，不影响其他来源。
  在线程中读取，缓存只保留小型显示位置；文件路径、类型、offset、size/mtime变化会使缓存失效。
- 前端优先使用真实实时/最后遥测和路口位置；这些都不可用时使用录制位置，显示“素材位置 · 非实时”。
  检测结束不再把旧回放遥测及遗留flying状态当作实时飞行，图标依然保留，点击仍保留SourceProfile与路口绑定。
- 该显示坐标不参与地理质量、Lane/Link、路网标注或统计计算；生产路网开关保持false，不额外读取Doris，
  不补造路口快照、不把录制GPS当作经过测量的路口中心。无真实坐标的来源继续不绘制。

## 验证与范围

  停止后使用素材位置且is_flying/runtime_flying/telemetry_fresh均为false。
- 后端覆盖SRT与JSON、同步offset、WGS84→GCJ-02、缺失/越界路径、无GPS、素材更新及异常文件隔离。
- 本机16/16已登记来源均可从真实遥测读出录制位置，不需要启动检测器或读取路网。
- 原生Platform更新后，浏览器无活动检测任务时读取到7个登记无人机图标，其中3个使用素材位置；
  点击经十路东段离线图标正确进入`INT_MP4820_JINGSHI_EAST_CORRIDOR`及`SRC-MP4820-JS-0813-EW`，
  已返回首页。新位置接口重复查询本机约18–25ms，仅是本机缓存观测，不作为生产延迟承诺。
