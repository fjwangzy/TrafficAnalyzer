## 1. 分册目标与边界

### 1.1 目标

- 在有效监测窗口内，把无人机视频、遥测、标定和权威路网上下文转换为路口、进口 Link、出口 Link、可识别车道及转向维度的实时态势。
- 输出交通参与者检测/跟踪、速度、方向、流量、排队、车头时距、0—10 拥堵指数、轨迹及质量状态，并能解释统计样本和降级原因。
- 所有可映射结果携带权威 `inter_id + road_data_version`；Link/车道低置信度、歧义或无主数据时必须输出 `unmapped`，不得拼造权威 ID。
- 向智慧交通主平台提供可靠、可追溯、可幂等重传的态势快照和 AI 拥堵结果，并接收确认/驳回反馈用于质量评估。
- 在视频、遥测和消息链路正常且对应模式运行时，拥堵形成至 AI 结果输出目标不超过 30 秒；“拥堵形成”的标注口径与窗口参数为 `【验收阻断：S1-TBD-002】`。
### 1.2 非目标

- 不建设路网权威底库，不执行信号配时/控制、航线规划或多无人机调度；不承担跨来源合并、统一警情编号、人工研判、派警、处置、解除和归档，相关状态以智慧交通主平台为唯一真源。本地确认/驳回仅表示 AI 复核，不等同于警情确认或执法定案；不扩展货车细分类。3—5 秒预测只作辅助展示和下游输入，预测方案由 S2 统一负责：本期工程基线拟采用运动学外推 + 卡尔曼，但在 S2-TBD-001/P-TBD-001 关闭前，不视为学习型预测合同责任已删除。

## 3. 前置条件、输入与输出

### 3.1 前置条件

1. 任务由权威 `inter_id` 启动，并冻结一个已发布的 `road_data_version`；权威 schema、有效期和代码表以 S5 评审结果为准。
2. RoadContextAdapter 已获得路口、进口/出口 Link、车道及拓扑只读快照，或命中最近一次已验证缓存；逐帧管道不得直接查询远程路网库。
3. 视频帧具有可排序时间戳；视频与遥测的时钟源、容忍偏差和缺帧判定阈值为 `【待确认：S1-TBD-010】`。
4. 遥测标定或静态参考点标定至少一种可用；输出米制速度/距离前必须通过单应性和运动补偿质量检查。
5. 车道级输出为条件能力：只有视觉车道存在、车辆命中且绑定满足冻结质量门槛时，才输出权威 `lane_id` 统计。
6. 模型版本、类别映射、运行配置、视觉绑定版本和接口 `schema_version` 可追溯。
7. 主平台鉴权、回执、重试、死信和复核反馈契约由 S6 冻结；未联调前不得宣称完成主平台闭环。
### 3.2 输入

| 输入 | 必需性 | 关键内容 | 不可用时处理 |
| --- | --- | --- | --- |
| 视频帧/流 | 必需 | 帧、采集时间、相机/设备标识 | 停止新增统计，保留任务与链路告警 |
| 无人机遥测 | 条件必需 | GPS、高度、姿态、云台、相机参数、时间戳 | 切换已验证静态标定；否则停止米制指标 |
| 标定与运动补偿 | 米制指标必需 | 单应性、标定模式、质量状态、无人机位移/速度 | 相关字段为 `null`，不得用 0 伪装有效值 |
| 路网上下文 | 权威聚合必需 | `inter_id`、Link、Lane、拓扑、坐标语义、版本 | 缓存则 `stale`；无缓存则 `missing + unmapped` |
| 视觉区域配置 | 条件必需 | ROI、道路/车道多边形、停止线、人工绑定 | 无车道配置时只输出路口/Link 可用维度 |
| 模型与规则配置 | 必需 | 模型版本、类别映射、方向/排队/拥堵参数 | 校验失败回退上一批准版本并告警 |
| 主平台任务/反馈 | 集成必需 | 任务上下文、接收回执、确认/驳回及原因 | 本地感知可继续，出站结果持久化待重传 |
### 3.3 输出

| 输出 | 粒度/时机 | 主要内容 | 质量要求 |
| --- | --- | --- | --- |
| 态势快照 | `【待确认：窗口与步长，S1-TBD-002】` | 活跃数、流量、均速、转向、排队、车头时距、拥堵指数 | 携带窗口、样本量、覆盖率、质量状态 |
| 完成轨迹 | 轨迹结束时 | 类别、入口/出口 Link/Lane、转向、速度、像素/世界/GCJ02 轨迹 | 坐标和地图匹配质量可解释 |
| AI 拥堵结果 | 触发/更新/恢复规则由 `S1-TBD-002` 冻结 | 指数、等级、贡献因子、范围、证据引用 | 只上送结果，不维护主平台处置状态 |
| 页面与导出 | 实时/历史查询 | 地图/视频叠加、表格、趋势、CSV | 与查询条件、路网版本和质量标记一致 |

## 4. 业务主流程与状态

1. 主平台或本地受权入口提交任务及 `inter_id`，系统校验身份、视频源和任务参数。
2. 路网适配器加载已发布快照并冻结 `road_data_version`，执行坐标语义、空间范围和视觉绑定一致性校验。
3. VideoReader 对齐视频帧与遥测；检测/跟踪节点产生稳定目标 ID 和原始类别结果。
4. 标定及运动补偿节点把像素轨迹转换为局部世界坐标；满足质量门槛时再转换为 GCJ02。
5. 轨迹按人工绑定、主数据几何、轨迹候选、模型候选的顺序进行地图匹配；未过门槛统一进入 `unmapped`。
6. 方向能力始终在轨迹条件满足时输出；车道能力仅在有效车道数据且点位命中时叠加，不依赖人工切换模式。
7. 统计器按同一窗口聚合路口、Link、车道和转向指标，计算 0—10 拥堵指数及贡献因子，并保留样本量和覆盖率。
8. 系统生成态势快照、完成轨迹和满足规则的 AI 拥堵结果，经 Kafka/平台适配器投递并记录回执、重试或死信。
9. 页面通过实时通道展示结果和降级状态；历史查询按原 `road_data_version` 解释，版本升级不得回写历史数据。
10. 主平台回传确认/驳回及原因，系统只更新 AI 质量样本关联；派警和处置状态不得写入本地业务状态机。
11. 任务结束时停止新增帧，完成可判定轨迹和窗口收尾，记录未完成样本、发送状态与任务质量摘要。

## 6. 业务规则与统计口径

### 6.1 通用规则

| 编号 | 规则 |
| --- | --- |
| S1-BR-001 | 权威聚合键为 `inter_id + road_data_version`，并按需追加 `link_id/lane_id/link_role/direction`；本地 `road_N` 只能作为旧接口兼容别名。 |
| S1-BR-002 | `road_context_status` 使用 `ok/stale/missing/version_mismatch`；低置信度、歧义、版本不匹配或无缓存时不得输出推测的权威 ID。 |
| S1-BR-003 | 地图匹配优先级为人工确认绑定 > 主数据几何 > 轨迹候选 > 模型候选；门槛 `【待确认：S1-TBD-006】`，未通过时方法为 `unmapped`。 |
| S1-BR-004 | 单次任务冻结路网版本；新版本只对新任务生效并触发绑定差异检查，历史统计/轨迹/事件不得改写。 |
| S1-BR-005 | `null` 表示不可计算或不适用，数值 0 只表示经过有效计算后结果为零；页面、导出和消息保持一致。 |
| S1-BR-006 | 同一轨迹在同一统计范围和窗口内按唯一 `track_id` 去重；跨进程/重启后的标识作用域与唯一性方案由 `S1-TBD-008` 随事件契约冻结。 |
| S1-BR-007 | 方向分类角度、最小轨迹时长、最小点数和最小位移均配置化并记录版本；不满足条件输出 `unknown`。 |
| S1-BR-008 | 车道统计只覆盖有效绑定且点位命中的车辆；未命中车辆仍可进入具备依据的 Link/路口统计，且计入未匹配率。 |
| S1-BR-009 | AI 拥堵等级不直接等于主平台警情等级；映射、全局去重和处置由主平台负责。 |
### 6.2 指标口径

| 指标 | 计算对象与公式 | 必须伴随字段 | 未冻结项 |
| --- | --- | --- | --- |
| 当前活跃数 | 快照时刻范围内有效、未结束的唯一轨迹数 | `active_vehicle_count`、`sample_size`、`coverage_ratio` | 有效轨迹门槛 |
| 流量 | 窗口内满足计数事件的唯一轨迹数；换算值为 `count / effective_window_sec × 60` | `flow_count`、`flow_rate_vpm`、`window_start/end`、`count_method` | 窗口、步长、计数线/完成轨迹口径 |
| 平均速度 | 窗口内有效轨迹平滑速度的算术平均；无有效样本为 `null` | `avg_speed_kmh`、`speed_sample_size`、`calibration_quality` | EMA 参数、异常值规则 |
| 转向流量 | 按入口 Link、出口 Link及 `straight/left_turn/right_turn/u_turn/unknown` 交叉聚合 | 入口/出口 ID、方向、计数、未知数 | 角度/拓扑判定门槛 |
| 排队车辆数 | 速度低于阈值且持续达到时长、处于有效排队范围的唯一车辆数 | `queued_vehicle_count`、阈值版本、质量 | 速度阈值、持续时长、空间范围 |
| 排队长度 | 有效停止线至同一队列队末车辆的世界坐标距离；缺停止线或有效 H 时为 `null` | `queue_length_m`、`queue_method`、`stop_line_id` | 间隙分段与异常队列规则 |
| 车头时距 | 同车道/同方向相邻车辆通过同一计数位置的时间差 | 均值、最小值、样本数、计数位置 | 合理区间、统计窗口 |
| 低速比例 | 有效范围内低速车辆数 / 有效速度车辆数；分母为零时为 `null` | 分子、分母、阈值版本 | 低速阈值 |
| 拥堵指数 | 密度贡献（0—4）+ 排队贡献（0—3）+ 低速贡献（0—3），截断至 0—10 | 总分、三个贡献因子、等级、公式版本 | 分档、预警/恢复阈值、滞回时间 |

总 PRD 中“25 帧均值、存活 >3 秒、拥堵指数 ≥7”和设计文档中的 5 km/h、8 m 等数值均作为候选设计输入；在 S1-TBD-002 关闭前不得视为冻结生产阈值。若最终口径变更，必须升级规则/配置版本并补充回放对比证据。
## 7. 数据、接口与页面

### 7.1 通用消息字段

| 字段 | 必需性 | 说明 |
| --- | --- | --- |
| `schema_version`、`msg_type` | 必需 | 消息契约版本和 `uav_stats/uav_track_complete/uav_ai_event`；拥堵由 `uav_ai_event.event_type` 区分，枚举见 S1-TBD-008 |
| `occurred_at`、`window_start`、`window_end` | 按类型必需 | 使用约定时区/时间格式；统计必须有窗口，轨迹必须有首尾时间 |
| `source_system`、`source_event_id`、`idempotency_key` | 事件必需 | 主平台最小契约；重复幂等键不得生成重复事件 |
| `device_id`、`camera_id`、`task_id` | 按契约必需 | 数据来源和任务关联；字段命名/必填性由 S6 冻结 |
| `intersection_id`、`inter_id` | 必需 | 前者为兼容/平台对象标识，后者为权威路口 ID；映射规则必须显式 |
| `road_data_version`、`road_context_status` | 必需 | 所有统计、轨迹和事件均保存原版本及上下文状态 |
| `link_id/lane_id`、`entry_*`、`exit_*` | 条件必需 | 可可靠匹配时输出，否则为空并说明 `unmapped` |
| `map_match_method`、`map_match_confidence` | 必需 | `manual/master_geometry/trajectory/model/unmapped` 及置信度 |
| `position_gcj02`、`trajectory_world_m`、`trajectory_gcj02` | 按类型条件必需 | 坐标可用才输出，同时携带坐标/标定质量 |
| `quality_status`、`quality_reasons` | 必需 | 表示完整、降级或无效及原因；枚举由 S5/S7 冻结 |
| `model_version`、`config_version`、`binding_version` | 必需 | 支持复现检测、规则和视觉绑定结果 |

统计负载还应包含维度键、活跃数、流量、均速、排队、车头时距、拥堵指数/贡献因子、样本数和覆盖率。完成轨迹负载还应包含 `track_id`、参与者类别、转向、时长、平均/最大速度、入口/出口 ID 与轨迹点。AI 拥堵结果遵守总 PRD 的最小事件契约，并包含 `severity`、`confidence`、`evidence_refs`；主平台返回 `platform_event_id`、接收时间和接收结果。
### 7.2 传输与兼容

- 周期统计目标 Topic 为 `uav_statistics_{camera_id}`，完成轨迹为 `uav_track_complete_{camera_id}`；主平台 AI 拥堵结果统一进入 `uav_ai_events`。频率、超时、外部 API/Topic 和错误码由 `S1-TBD-008` 与 `S6-TBD-001/003/004` 冻结，当前为 `【验收阻断】`。
- 实时页面目标通道为 `uav_intersection:{intersection_id}`，其中 `msg_type` 使用 `uav_stats/uav_track_complete/uav_conflict`；迁移期兼容旧通道须有退役日期，不得长期发布语义不同但同名字段。
- 目标持久化为 database=`road9`：周期态势写 `uav_traffic_metrics`，完成轨迹主记录/点序列写 `uav_track_events` 与 `uav_track_points`，需投递主平台的拥堵事件写 `uav_ai_events` 与 `uav_event_outbox`；所有来源标识固定为 `source_system=uav_traffic_analyzer_ai`。
- `road_1..road_N` 和本地车道键仅作向后兼容，必须同时保留权威字段、版本和映射状态；不得供新业务作为主键。
- 事件投递使用持久化出站队列、指数退避、幂等键和死信告警；次数、间隔和死信时限由 S6 冻结。
### 7.3 实时态势页面

1. 查询区：路口、时间范围、进口/出口 Link、车道、转向、参与者类别、质量状态、路网版本；默认值和可查询跨度 `【待确认】`。
2. 摘要区：有效监测状态、当前活跃数、窗口流量、均速、排队数/长度、拥堵指数、`unmapped` 数量；空值必须说明原因。
3. 地图/视频区：轨迹、ROI、停止线、Link/车道、方向和质量叠加；原始视频与结构化结果使用同一时间基准。
4. 明细区：按进口 Link × 出口 Link × 车道 × 转向展示指标、样本数、窗口、匹配方法和版本，支持下钻至完成轨迹。
5. 趋势区：展示流量、速度、排队、拥堵指数和有效覆盖率，不连接跨越数据缺口的折线。
6. 操作：历史回放、CSV 导出和经授权的 AI 阈值配置；阈值发布需校验、审批、版本和回滚，不提供派警/处置按钮。
7. 降级横幅：显示 `stale/missing/version_mismatch`、标定无效、视频中断和消息积压；`unmapped` 数据不得被页面静默过滤。
## 8. 异常、降级与人工兜底

| 异常 | 自动处理 | 输出/人工动作 |
| --- | --- | --- |
| 路网远程库不可用且有已验证缓存 | 冻结缓存版本继续任务 | `road_context_status=stale`，告警并提示数据时间 |
| 路网无缓存或版本不匹配 | 保留本地像素/可用世界轨迹，停止权威 Link/Lane 聚合 | ID 置空、`unmapped`；数据/GIS 人员校正 |
| 自动绑定低置信度或歧义 | 不选择“最像”的权威 ID | 进入 `unmapped` 校正清单，人工确认后生成新绑定版本 |
| 无车道多边形或车辆未命中 | 跳过车道级统计 | 保留可用方向/路口/Link 结果并记录未匹配率 |
| 遥测缺失或超时 | 使用已验证静态参考点标定 | 标记标定模式；无可用替代时米制值为 `null` |
| 单应性/运动补偿质量不合格 | 停止速度、距离和 GCJ02 有效输出 | 保留像素轨迹与原因，不以像素距离冒充米 |
| 视频中断、乱序或大面积丢帧 | 暂停新增统计并等待恢复，窗口记录有效覆盖 | 页面显示中断；是否自动终止任务 `【待确认】` |
| 检测节点失败 | 隔离失败帧并触发管道健康策略 | 可显示最后成功结果为“陈旧”，但不得重复计数或伪造新快照 |
| 规则配置无效 | 校验拦截并回退上一批准版本 | 告警管理员，记录失败配置哈希和原因 |
| Kafka/主平台不可用 | 本地持久化、重试、恢复重传，超限进死信 | 不静默丢弃；运维处理死信，主平台按幂等键去重 |
| 主平台驳回 AI 结果 | 关联驳回原因作为质量反馈 | 不在本地改写主平台警情或处置状态 |
| 任务非正常结束 | 保存可恢复状态和未投递消息 | 标记任务质量不完整，人工决定重跑/补采 |

## 11. 依赖、风险与待补充项

### 11.1 关键依赖与风险

- S5 未冻结权威 schema、坐标语义、代码表、版本有效期和绑定质量门槛前，Link/车道验收无法定稿。

- 拥堵指数候选公式可能与指挥员感知、信号周期或不同路口几何不一致，需试点校准并保留公式版本。
- 预测精度和等效验收受投标偏差确认影响；未取得书面确认前不得把运动学方案视为已满足全部合同要求。
