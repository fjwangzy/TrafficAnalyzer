| 文档属性 | 内容 |
| --- | --- |
| 所属项目 | 智慧交通整体项目下的无人机 AI 子项目 |
| 上位文档 | `docs/generated/2026-06-29-uav-traffic-ai-prd.md` v1.8 |
| 分册状态 | 可开展 R1 范围与流程评审；指标和外部依赖未冻结 |
| 主要评审方 | 事故处理部门、测绘/测试、法制、网安、大项目平台方、无人机作业方 |

> 本分册定义无人机辅助量算、现场示意数据和可追溯材料的产品需求。系统输出仅供事故现场处置和人工复核，不替代法定事故勘查、责任认定、人工签章或案件归档流程，也不对材料的法律效力作自动判断。

## 1. 分册目标与边界

### 1.1 目标

1. 在符合现场指挥和无人机作业安全条件时，减少人员进入危险路面的非必要量测作业。
2. 形成可人工复核的点、线、折线和面量算结果，并明确坐标、质量状态和误差估计。
3. 使每项结果可追溯到原始采集材料、遥测、标定参数、控制点、算法版本和操作记录。
4. 输出现场平面示意数据、量算清单、报告预览和材料引用，供智慧交通主平台或案件系统承接后续流程。

### 1.2 非目标

- 不自动进行事故责任认定、违法定性或法定文书签章。
- 不替代现场安全管控、道路封控、人工复测和其他外部勘查程序。
- 本期只定义平面量算；高程、三维重建、体积量算和摄影测量建模为 `【范围冻结：不纳入本分册当前范围】`。
- 不承诺自动识别全部事故车辆、痕迹和散落物；人工标注是必备兜底，自动识别对象清单为 `【待确认】`。
- 不重复建设智慧交通主平台的案件、处置、签章和长期归档状态机。

### 1.3 当前基础与缺口

| 能力 | 经文档核实的现状 | 本分册要求 |
| --- | --- | --- |
| 视频与遥测 | 已支持 MP4/RTSP、MQTT/JSON/SRT 帧级取数 | 复用并增加测绘质量快照 |
| 平面映射 | 已有单应性、运动补偿和 ENU 局部坐标基础 | 增加控制点、残差和量算质量门禁 |
| 地理坐标 | GCJ02 归一化和路网语义仍在规划/核验 | 不得把未验证坐标标记为合格 |
| 测绘业务 | `MeasurementNode`、`GeoRefNode`、`EvidenceFrameNode` 尚属规划 | 新建并按本分册验收 |
| 平台能力 | 已有通用任务、JWT 和管道管理基础 | 测绘专用 API、页面、存储和报告待开发 |
| 既有测试 | 单路口管道基线为 56 PASS | 不代表事故量算精度或证据完整性已通过 |

## 2. 用户、角色与任务场景

| 角色 | 本分册职责 | 明确限制 |
| --- | --- | --- |
| 事故处理民警 | 创建/接收任务、选择量算对象、人工标点、复核结果、发起导出 | 仅能访问分配给自己的任务；是否具有最终签章权 `【待确认】` |
| 无人机作业人员 | 按现场指令采集，关注飞行与影像质量，执行补拍 | 飞行授权和现场安全责任遵循项目外部制度，系统不代替其判断 |
| 技术复核人员 | 复核控制点、坐标链、误差和量算版本 | 角色是否独立设置及复核分离规则 `【待确认】` |
| 系统管理员/运维 | 配置、健康监控、故障处理 | 不得修改已生成的原始材料或代替业务复核 |
| 主平台/案件系统 | 提供任务关联信息，接收成果和引用，维护后续业务状态 | 接口和归档流程 `【外部依赖】` |

- **事故民警主流程场景**：接收/创建任务，核对事故位置和对象，在安全与质量前置通过后选择采集批次，人工标注/校正点线面，逐项复核后生成报告并投递主平台。
- **事故民警退化场景**：快速路/高速、夜间、遮挡或 RTK/网络退化时，先查看受影响区域和补拍建议，选择补拍、增加控制点或转人工量测；适用性和必留人工手段由事故处理部门与作业方确认。

## 3. 前置条件、输入与输出

### 3.1 作业安全与启动条件

系统在开始有效采集前应展示并记录以下核验结果，但不自行批准飞行或道路作业：任务来源与现场位置、授权作业人员、现场指挥确认、可飞状态、采集区域、时间同步、设备/相机/标定版本和存储余量。具体检查表及失败后的作业规则为 `S3-TBD-007`。

质量门禁分三层：

1. **作业前置门禁**：外部安全条件未确认时，不允许将采集标记为“有效测绘采集”；是否允许继续预览由作业制度决定。
2. **采集质量门禁**：持续显示 RTK/定位、遥测新鲜度、姿态、飞行稳定性、清晰度、曝光、遮挡、覆盖度、单应性/控制点状态；阈值未冻结前只显示观测值与 `unverified`。
3. **成果门禁**：质量不满足已批准口径时，可保存草稿和补拍材料，但不得进入“技术复核通过/可交付”。

### 3.2 输入

| 输入 | 最低要求 | 不可用处理 |
| --- | --- | --- |
| 任务上下文 | 任务ID、事故时间/位置、任务来源、创建人与分配人 | 任务ID来源未冻结时使用本地ID并保留外部ID空值 |
| 视频/关键帧 | 原始采集引用、帧号、采集时间 | 缺失则相关量算不可交付 |
| 遥测 | 飞行位置、高度、姿态、云台、质量/时间信息 | 标记退化；超过批准范围则补拍或人工量测 |
| 相机与标定 | 相机参数、单应性/配准方法及版本 | 无有效版本时禁止输出合格量算 |
| 控制/参考数据 | 控制点或标准尺的坐标、来源和质量信息（如采用） | 不得用待测对象同时充当独立真值 |
| 路网上下文 | 可选 `inter_id/link_id/lane_id/road_data_version` | 无匹配时置空并标记 `unmapped`，不得伪造权威ID |

### 3.3 输出

- 测绘任务及状态、采集批次、质量检查结果和补拍建议。
- 点坐标、线/折线长度、面面积与周长、对象/痕迹标注及各自质量状态。
- 平面示意数据、量算清单、误差/残差说明、报告预览和版本。
- 原始材料引用、内容哈希、派生关系、操作审计和导出记录。
- 主平台接收所需的任务关联键、幂等键、成果摘要、材料引用、schema 版本和投递状态。

## 4. 业务主流程与状态

创建/接收任务 → 核验作业前置条件 → 到场采集与实时质量预检 → 选择有效采集批次 → 自动候选/人工标点 → 点线面量算 → 质量检查与误差估计 → 人工技术复核 → 生成报告与完整性校验 → 幂等投递主平台 → 接收回执。补拍可从质量检查或复核环节返回采集；人工修订必须形成新版本。

### 4.1 本地任务状态机

| 当前状态 | 触发 | 目标状态 | 操作角色/说明 |
| --- | --- | --- | --- |
| `created` | 开始前置核验 | `prechecking` | 民警/作业人员 |
| `prechecking` | 条件和质量可用 | `ready` | 系统记录依据，不代表批准飞行 |
| `prechecking` | 条件不满足 | `precheck_failed` | 允许整改后重检 |
| `ready` | 开始有效采集 | `collecting` | 作业人员 |
| `collecting` | 提交采集批次 | `measuring` | 系统/事故民警 |
| `measuring` | 提交技术复核 | `pending_review` | 事故民警 |
| `pending_review` | 需修订或补拍 | `returned` | 记录原因及返工类型 |
| `returned` | 选择修订/补拍 | `measuring` / `collecting` | 原版本保留 |
| `pending_review` | 技术复核通过 | `technical_reviewed` | 不等同于法定审核或责任认定 |
| `technical_reviewed` | 报告完整且投递完成 | `completed` | 保存主平台回执；主平台归档状态独立 |
| 任一非终态 | 授权取消/不可恢复错误 | `cancelled` / `error` | 原因、操作者和已有材料均留痕 |

成果投递另用 `generated/delivering/delivered/delivery_failed`，不得将其混同任务状态或主平台案件状态。

### 5.1 量算与证据规则

| 编号 | 规则 |
| --- | --- |
| S3-BR-001 | 长度和面积必须在经验证的米制平面坐标中计算；GCJ02 用于定位/展示，不直接在经纬度数值上求距离或面积。 |
| S3-BR-002 | 每项结果保存图像坐标→标定/单应性→ENU/米制坐标→可选 GCJ02 的转换链和版本。 |
| S3-BR-003 | `quality_status` 至少区分 `unverified/pass/warn/fail/unavailable`；阈值未冻结时不得使用 `pass`。 |
| S3-BR-004 | 控制点、标准尺或基准设备的来源和质量记录必须独立可追溯，不能以模型自身输出作为验收真值。 |
| S3-BR-005 | 自动候选不覆盖人工结果；人工修改须记录操作者、时间、原因和前后值。 |
| S3-BR-006 | 每个可交付成果必须绑定唯一证据链；证据帧保留原始未压缩材料及哈希，不得被后处理覆盖；裁剪、脱敏、增强和示意图均作为派生物引用原件哈希。 |
| S3-BR-007 | 报告在外部签章流程完成前明确标识为“无人机辅助量算结果，需人工复核”，不得显示为责任认定结论。 |
| S3-BR-008 | 测绘/案件材料不适用普通结构化热数据的自动清理；实际保留期限、删除审批和原件格式由法制/网安冻结。 |
| S3-BR-009 | 道路主数据版本在任务内冻结；缺失或不一致时保留本地几何并降级，不回写重解释历史成果。 |

## 6. 数据、接口与页面

### 6.1 核心数据对象

| 对象 | 必备字段（摘要） |
| --- | --- |
| `uav_survey_tasks` | task_id、external_task_id、source、scene_location、可选道路ID、assignee、state、created_at、版本 |
| `uav_capture_batches` | batch_id、视频/帧引用、时间范围、遥测与标定版本、quality_checks、coverage、hash |
| `uav_survey_measurements` | measurement_id、type、source_frame、image_geometry、metric_geometry、value/unit、error_estimate、quality_status、version |
| `uav_scene_annotations` | annotation_id、category、geometry、source、confidence、review_state、version |
| `uav_survey_reports` | report_id、task_id、measurement_refs、evidence_refs、quality_summary、template_version、content_hash |
| `uav_audit_logs` | actor、action、target、before/after version、reason、time、request_id |

量算对象的坐标系、单位、空值原因和质量状态必须显式保存。道路ID必须与 `road_data_version` 同时保存；无法匹配时使用 `unmapped`，不以本地序号冒充权威ID。测绘业务数据的目标存储为 PostgreSQL `database=road9`，所有本子项目自建物理表统一使用 `uav_` 前缀；事故测绘任务、量算、报告和审计数据不以 InfluxDB 作为目标存储。

### 6.2 规划接口与消息

测绘专用 REST API、统一消息和数据库表当前尚未实现。建议能力包括任务创建/查询、前置核验、采集批次、量算草稿、提交/退回/技术复核、报告生成、导出和投递状态查询。测绘成果统一投递至 `uav_ai_events`，消息固定使用 `msg_type=uav_ai_event`、`event_type=survey_result`；最终 REST 路径、错误码、schema、超时和重试由 S6 接口评审冻结。

投递主平台至少包含：`source_system=uav_traffic_analyzer_ai`、`source_task_id`、`idempotency_key`、外部任务关联键、任务状态、现场位置、`inter/link/lane`及路网版本（适用时）、量算摘要、质量状态、报告/材料引用、各内容哈希、算法/模板/schema 版本、生成时间。大文件优先传不可变授权引用而非直接塞入事件消息，访问与有效期策略 `【外部依赖：主平台/网安】`。

### 6.3 页面与交互

1. `/survey`：按任务ID、来源、位置、状态、人员和时间查询；创建、领取、取消、查看投递状态。
2. `/survey/{id}/capture`：展示视频/关键帧、遥测和质量面板，选择有效批次、标记覆盖缺口和发起补拍。
3. `/survey/{id}/measure`：图层式标点/线/面/对象，吸附和撤销重做，实时显示单位、质量、来源帧和版本；自动候选与人工结果视觉区分。
4. `/survey/{id}/review`：逐项对照原帧、示意图、控制点、误差和编辑历史，退回时必填原因及“修订/补拍”类型。
5. `/survey/{id}/report`：报告预览、完整性检查、版本对比、导出和主平台回执；未过门禁时禁用“可交付”。

权限沿用总 PRD：事故民警仅访问分配任务；管理员不因管理权限获得业务复核结论权。证据原件调阅、报告导出和删除申请的细粒度权限为 `【待确认】`。

## 7. 异常、降级与人工兜底

| 异常 | 系统行为 | 人工兜底/结果限制 |
| --- | --- | --- |
| RTK、遥测或时间同步退化 | 标记原因和影响范围，停止给受影响结果标记 `pass` | 补拍、增加控制点或人工量测 |
| 画面模糊、过曝、遮挡或覆盖不全 | 标出不合格帧/区域并给出补拍清单 | 选择其他帧或现场补拍 |
| 无人机移动/姿态变化过大 | 切分采集批次，禁止混用不兼容标定 | 重新稳定采集 |
| 标定、控制点残差异常 | 阻止成果门禁，保留诊断信息 | 重标定、增加/更换控制点或人工复测 |
| 自动对象识别失败 | 不生成虚假对象或坐标 | 允许人工标注并标记 `source=manual` |
| 路网/GCJ02 上下文缺失 | 输出本地米制几何，权威ID置空并降级 | 人工核对位置；不得伪造ID |
| 网络/主平台中断 | 本地持久化、幂等重试、失败告警 | 恢复后重传；不重复创建成果 |
| 存储余量不足 | 采集前告警；无法保证原始材料时阻止有效采集 | 扩容/转储后继续，不删除未归档材料 |
| 哈希不一致或材料缺失 | 标记完整性失败并禁止交付 | 从可信原件恢复或重新采集；全程留痕 |
| 报告生成失败 | 量算和材料保留，报告状态为失败 | 重试生成或导出结构化数据供人工制表 |
| 现场突发安全风险 | 系统记录中止原因，不下达飞行/交通处置指令 | 服从现场指挥与作业制度，必要时取消任务 |

## 8. 非功能需求

| 编号 | 要求 |
| --- | --- |
| S3-NFR-001 | **完整性**：任务、原件、派生物、量算、报告和投递回执形成可验证引用链；哈希算法和不可变存储方案由网安冻结。 |
| S3-NFR-002 | **安全**：最小权限、任务级数据隔离、传输/存储保护、敏感展示副本与原件分离，具体基线 `【外部依赖：网安】`。 |
| S3-NFR-003 | **审计**：创建、标注、修改、复核、导出、调阅和删除申请均可查询，日志不可由普通业务用户修改。 |
| S3-NFR-004 | **可用性**：弱网下允许本地采集与编辑草稿，恢复后幂等同步；离线时明确展示未投递状态。 |
| S3-NFR-005 | **性能**：总 PRD 的单事故测绘耗时目标为 ≤15 分钟，但计时起止、场景复杂度和各环节预算由 `S3-TBD-012` 冻结，当前为 `【验收阻断】`。 |
| S3-NFR-006 | **可解释性**：每项量算可一键定位原帧、选点、转换链、控制点、质量因子和版本。 |
| S3-NFR-007 | **兼容性**：支持版本化 API/schema、路网和报告模板；升级不得静默重算历史成果。 |
| S3-NFR-008 | **容量**：按总 PRD 暂以不少于 180 天测绘材料进行容量设计，不代表最终保留期限；不得进入普通 30 天自动清理。 |

## 9. “≤3m”指标冻结与验收

总 PRD v1.6 及更早版本曾将距离和面积统一表述为“≤3 米”，v1.7 起已校准为分量纲冻结，v1.8 继续沿用：面积误差单位不能用米，点位误差、长度误差和面积误差也不能共享同一计算公式。本分册不推定任何法定阈值；`S3-TBD-001/002` 在批准前均为 `【验收阻断】`，不得以单个演示样本宣称达标。

| 对象 | 建议报告指标 | 计算方式 | 当前状态 |
| --- | --- | --- | --- |
| 点位 | 平面位置误差（m） | 在同一验证米制坐标系中，与独立真值计算二维距离 | 阈值/统计量待冻结 |
| 线/折线 | 绝对误差（m）及相对误差（%） | 系统长度与独立基准长度对比 | “≤3m”是否适用待冻结 |
| 面 | 绝对误差（m²）及相对误差（%） | 系统面积与独立基准面积对比 | 必须另定阈值 |
| 地图位置 | GCJ02/路网对齐误差（m） | 与经确认坐标基准对比 | 与量算误差是否合并待冻结 |

验收方案必须冻结：测量对象和参考点定义、基准设备/控制点及其质量、独立真值采集人、飞行高度/视角/光照/遮挡/RTK状态分层、样本量、异常值规则、均值/RMSE/P95/最大值等统计口径、通过规则和复测规则。

### 9.1 分场景验收用例

| 编号 | 场景与操作 | 预期结果 |
| --- | --- | --- |
| S3-AC-001 | 创建道路事故任务并完成前置核验 | 任务、人员、位置、设备与核验记录完整，状态转换合法 |
| S3-AC-002 | 缺失安全确认或有效标定时尝试有效采集 | 不得标记为有效/合格采集，原因和整改入口清晰 |
| S3-AC-003 | 标准场景完成点、线、折线和面量算 | 结果、单位、选点、转换链、质量和版本均可复核；精度按冻结方案判定 |
| S3-AC-004 | 斜视、不同高度和姿态场景量算 | 分层报告，不以总体均值掩盖失败场景 |
| S3-AC-005 | 夜间、阴影、反光、遮挡或覆盖不全 | 质量降级被识别，低质量区域进入补拍/人工兜底，不伪造结果 |
| S3-AC-006 | RTK/遥测中断后继续任务 | 受影响时段及量算被正确标记，恢复后批次边界清楚 |
| S3-AC-007 | 自动候选错误后人工增删改 | 自动与人工来源可区分，修改前后版本和原因可追溯 |
| S3-AC-008 | 技术复核退回补拍并再次提交 | 原成果不覆盖，补拍批次与新版本正确关联 |
| S3-AC-009 | 生成示意数据和报告 | 内容、质量声明、材料索引、模板/算法版本和报告哈希完整 |
| S3-AC-010 | 篡改派生文件或删除引用材料 | 完整性校验失败，阻止交付并产生审计/告警 |
| S3-AC-011 | 主平台断连、恢复和重复投递 | 本地成果不丢失，相同幂等键不产生重复成果，回执可查 |
| S3-AC-012 | 非任务人员查看/导出原件 | 权限拒绝且留审计；授权事故民警只能访问任务范围数据 |
| S3-AC-013 | 路网版本缺失或地图匹配失败 | 本地量算可留草稿，权威ID为空并标 `unmapped`，不伪造ID |
| S3-AC-014 | 统计端到端作业时长 | 按冻结的起止点和复杂度分层报告，未冻结前不判定 ≤15 分钟达标 |

发布门禁：P0 流程通过、所有成果可追溯、完整性失败可拦截、权限与弱网用例通过，且 `S3-TBD-001`、`S3-TBD-002`、`S3-TBD-004` 已取得书面结论。任何“技术复核通过”均不得替代主平台案件归档或法定程序。
