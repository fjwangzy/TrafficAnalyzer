# S4 执法检测分册 PRD

| 项目 | 内容 |
| --- | --- |
| 文档定位 | 无人机交通智能感知系统总 PRD 的 S4 业务分册 |
| 版本/日期 | v0.3 / 2026-07-15 |
| 评审对象 | 交通执法、法制、网安、算法、GIS、雷达设备方、测试、智慧交通主平台方 |
| 当前状态 | I4 本地候选线索工程闭环已实现；规则、权威围栏、法制证据、雷达设备与主平台契约仍阻断正式验收 |
| 输出性质 | AI 违法线索及证据数据，不是违法认定、处罚决定或法定测速结论 |

> 智慧交通主平台及法定业务系统负责人工研判、案件关联、处置、归档和处罚。本子项目只形成可追溯、可复核、可幂等投递的 AI 线索，不复制大项目业务闭环。

## 1. 目标、范围冻结与非目标
### 1.1 目标
1. 基于无人机视频、轨迹、路网、电子围栏和已批准规则生成待复核执法线索。
2. 对货车限行、超速、违停、区域滞留和占道候选进行事实计算；最终线索类型以 S4-TBD-001 批准清单为准。
3. 将视频估速、雷达原始测速和融合/选择结果分字段记录，完整保留来源和质量。
4. 自动封装帧、片段、轨迹、位置、规则、时间和哈希等证据数据并上送主平台。
5. 接收 AI 线索确认/驳回反馈，用于质量评估，不解释为处罚结论。

### 1.2 范围冻结

S4-SCOPE-001【范围冻结】：车辆分类仅复用现有模型的 truck/non_truck（货车/非货车）二分类。

- 不新增重型、中型、轻型货车及专项作业车细分模型或分类枚举。
- 不新增货车识别训练数据、样本库或训练任务；现有二分类只做质量基线评测，不以验收标注扩大模型训练范围。
- 不识别核定载质量，不依据外观推定车辆核载或法定车型。
- 规则不得使用本项目未提供的细分类或核载字段形成结论。
- 后续如需扩大范围，必须走正式合同和 PRD 变更流程。

### 1.3 非目标
- 不自动认定违法、立案或处罚，不替代法定人工审核。
- 不将视频 AI 估速表述为经检定雷达测速。
- 不在设备、检定和法制条件未知时承诺雷达测速证据效力。
- 不建设车牌识别、车辆登记信息核验或跨系统案件办理能力，除非另行批准。
- 不维护权威路网、围栏、限速和例外车辆底库，只消费已发布版本。

### 1.4 现状与目标能力分界
| 能力 | 现状判断 | 本分册目标 |
| --- | --- | --- |
| 检测、跟踪、世界坐标、运动补偿和视频速度 | 已有共性基础能力，不等于执法模型已验收 | 增加质量门禁和来源标记 |
| 货车识别 | 复用现有货车/非货车能力，质量基线待测 | 不扩类，只形成待复核事实 |
| 电子围栏与执法规则 | 目标新增，权威数据和规则未冻结 | 建设版本化匹配与可解释命中 |
| 雷达融合 | 目标接口，设备和检定条件未知 | 建设接入、关联和来源留痕；不得虚构设备结果 |
| 证据链 | 目标方案，法制效力和保存制度未确认 | 建设不可变引用、哈希和访问审计 |
| 主平台联动 | 规划契约，尚未形成正式接口 | 完成幂等、回执、重试和复核反馈联调 |

- Console2 `/enforcement/clues`、`/enforcement/truck`、`/enforcement/zones` 已切换真实 REST。页面不再显示模拟雷达、伪证据图、伪发布区域或模拟在线车辆。

| 法制审核人员 | 确认规则、证据要求和可采信边界 | 规则/证据审查 |
| 指挥员 | 查看线索态势和主平台接收状态 | 只读，不作处罚 |

| 算法/测试人员 | 评估分类、围栏、速度和规则质量 | 标注、评测，不得改原件 |

## 3. 前置条件、输入与输出
### 3.1 前置条件
1. 任务携带 task_id、inter_id 和冻结的 road_data_version，执法模式经授权启用。
2. 围栏和规则处于已发布、有效期内状态，并具有版本、审批人和适用辖区。
3. 视频、遥测和可选雷达使用可追溯时间基准；空间坐标和运动补偿通过质量门禁。
4. 原始证据存储、哈希、审计和主平台接收链路可用；不可用时按第 10 章降级。
5. 只有经确认设备、接口和检定状态的雷达数据才可进入雷达融合流程。

### 3.2 输入
| 输入 | 必要内容 | 质量要求 |
| --- | --- | --- |
| 视频/遥测 | 原始帧、片段索引、时间戳、RTK/姿态/云台 | 同步、定位和完整性可判断 |
| 目标轨迹 | track ID、truck/non_truck、置信度、ENU/GCJ02、速度 | ID 连续、分类和标定质量明确 |
| 路网/围栏 | inter/link/lane、区域多边形、坐标语义、版本、有效期 | 权威已发布快照 |
| 执法规则 | 类型、事实条件、时段、空间、车型二分类、例外、版本 | 法制/业务批准并可回滚 |
| 雷达数据 | 设备 ID、测量值、采集时刻、位置/方向、目标信息、检定元数据 | 来源真实、检定状态可验证 |
| 主平台契约 | schema、鉴权、回执、幂等、复核反馈 | 双方冻结 |

### 3.3 输出
- `uav_ai_events`（`event_type=enforcement_clue`）：规则命中事实、车辆二分类、位置、质量、规则版本和证据引用。
- speed_observation：视频速度、雷达速度、融合/选择速度及各自来源，字段互不覆盖。
- evidence_package：原始帧/片段不可变引用、轨迹、位置、规则快照、时间戳、哈希和审计元数据。
- diagnostics：未生成线索原因、围栏/规则/雷达状态、质量状态、投递和死信信息。

## 4. 线索主流程与状态
1. 任务启动时加载已发布路网、围栏、规则和版本快照；校验坐标、有效期和授权。
2. 检测、跟踪目标并输出 truck/non_truck 及置信度，不推导更细车型。
3. 计算围栏进入/离开/停留事实、视频速度和轨迹连续性。
4. 有雷达时先完成时钟、空间和目标关联，再保留原始雷达测量；无关联时不得融合。
5. 规则引擎基于已冻结事实和例外规则生成内部候选，并记录命中/排除原因。
6. 候选通过质量门禁后封装证据数据，生成 AI 待复核线索；证据失败不得输出“证据完整”。
7. 线索依次进入 generated、delivering、delivered 或 delivery_failed；断连后使用同一幂等键重传。
8. 主平台或授权复核端回传 reviewed_confirmed/reviewed_rejected 及原因；该状态只表示 AI 线索复核，不表示违法定案。

## 6. 业务规则
### 6.1 通用和车辆分类
| 编号 | 规则 |
| --- | --- |
| S4-BR-001 | 所有输出均为待复核线索；页面、消息和导出不得使用“已违法/已处罚”等自动结论文案。 |
| S4-BR-002 | vehicle_class 只允许 truck/non_truck；无法可靠二分类时字段置空并标记 unknown/low_confidence 质量状态，不得冒充货车或形成第三种车型。 |
| S4-BR-003 | 不产生货车细分类、核定载质量或法定车型字段；外部平台补充信息须注明独立来源。 |
| S4-BR-004 | 同一轨迹、同一规则、同一连续命中片段只生成一个同源线索；事实更新以 revision 追加。 |

### 6.2 围栏与规则
- 围栏匹配必须记录 fence_id、fence_version、source_coordinate_system、规则有效期和地图匹配质量。
- 货车限行候选至少同时满足：truck 事实有效、轨迹真实进入有效围栏、命中有效时段、未命中已知例外；阈值和例外清单待 S4-TBD-001。
- 边界抖动使用空间缓冲、进入/离开迟滞和连续轨迹验证；参数待批准，不在本分册虚构。
- 违停、滞留和占道必须使用连续轨迹、低速/停止、停留时长、区域类型及排除规则；阈值和业务区分待 S4-TBD-001/006。
- 围栏或规则版本不明、过期或签名/校验失败时，不生成高置信正式线索。

### 6.3 视频估速与雷达融合
- video_speed_kmh 只来自视频轨迹、米制标定和无人机运动补偿，并携带 speed_method、quality_status、估计误差/置信度。
- radar_speed_kmh 只来自指定 radar_device_id 的原始测量，并携带测量时间、设备位置/方向、检定证书标识及有效状态。
- 无雷达或雷达不可用时，radar_speed_kmh 和 fused_speed_kmh 为空，禁止复制视频值填充。
- 雷达关联必须校验时间差、空间距离、行驶方向和候选唯一性；阈值、歧义处理和设备协议见 S4-TBD-003/007。
- 原始视频值和雷达值发生差异时全部保留；融合/选择值须记录 fusion_method、decision_reason、规则版本和质量，不得覆盖原始值。
- 视频估速超过规则阈值只能生成超速线索。能否用于执法、容差如何设置及雷达是否必须，由法制和设备条件决定。

### 6.4 证据与人工复核
- 证据包至少包含原始帧、原始片段不可变索引、完整轨迹、GCJ02/ENU 位置、规则快照、时间戳、质量和内容哈希；总 PRD 的不少于 3 帧是设计基线，不代表法定充分性。
- 原件生成后不可修改；派生图片须保留 parent evidence ID、处理记录和哈希。
- 普通热数据近 30 天策略不得自动清理案件相关证据。当前“不少于 180 天”仅用于容量设计，法定期限见 S4-TBD-004。
- 人工复核须显示所有原始事实和质量告警，可确认 AI 线索、驳回或标记证据不足；不能在子项目内直接作出处罚。
- 复核、调阅、导出、补充和删除申请必须记录操作者、时间、原因、前后状态和审计 ID。

## 7. 目标字段契约
> 内部持久化与 REST 接缝已在 I4 实现；外部 S6 主平台契约仍待冻结。UAV 内部统一使用 <code>uav_ai_events</code>（<code>msg_type=uav_ai_event</code>、<code>event_type=enforcement_clue</code>），不再新建无前缀 enforcement Topic；本地实现不代表主平台外部接口或正式执法用途已验收。

目标持久化位于 database=`road9`：围栏、规则和线索详情候选表为 `uav_enforcement_zones`、`uav_enforcement_rules`、`uav_enforcement_clues`；事件主记录、投递和证据统一引用 `uav_ai_events`、`uav_event_outbox`、`uav_evidence_packages`、`uav_evidence_items`，不得复制其状态机。`source_system` 固定为 `uav_traffic_analyzer_ai`。

| 分类 | 必要字段 |
| --- | --- |
| 标识/状态 | source_system、source_event_id、idempotency_key、schema_version、event_revision、event_type、delivery_status、platform_event_id |
| 任务/时间 | task_id、occurred_at、window_start_at/end_at、detected_at、time_sync_status |
| 路网/围栏 | intersection_id（本地兼容键）、inter_id、road_data_version、road_context_status、link_id、lane_id、map_match_method/confidence、fence_id/version、position_enu/gcj02 |
| 车辆 | track_id、vehicle_class、class_confidence、classification_model_version |
| 规则 | clue_type（映射至通用 event_type）、rule_id/version、matched_facts、exclusion_result、severity、confidence、quality_status/reasons |
| 视频速度 | video_speed_kmh、video_speed_method、video_speed_quality、video_speed_uncertainty |
| 雷达速度 | radar_speed_kmh、radar_device_id、radar_measured_at、radar_calibration_ref/status、association_score/method |
| 融合结果 | fused_speed_kmh、fusion_method、speed_decision_basis；不适用时为空 |
| 证据 | evidence_package_id、evidence_refs、content_hashes、evidence_integrity_status |
| 复核 | review_result、review_reason、reviewed_by/at、platform_ack_at |

字段不适用或质量不满足时必须为空并给出原因。vehicle_class 不得出现重/中/轻型或专项作业车枚举；视频与雷达字段不得相互回填。

## 8. 页面与权限
1. 执法区域：地图查看围栏、版本、有效期、关联规则和发布状态。在 S4-TBD-002 关闭前，本地编辑只能形成候选配置，不得覆盖外部权威围栏；最终由本地发布还是由权威系统发布须通过责任边界确认。
2. 规则配置：展示事实条件、例外、版本差异、审批和回滚；未批准规则不可生效。页面是否具备权威发布权限由 S4-TBD-009 冻结。
3. 线索列表：按类型、路口、围栏、时间、复核、质量和投递状态筛选，车辆类型只显示货车/非货车/未知。
4. 线索详情：同步视频/轨迹/地图，分栏展示视频速度、雷达速度、融合结果、规则快照和质量原因。
5. 证据调阅：默认展示脱敏副本；原件查看、导出和删除申请使用独立权限并记录审计。
6. 运维监控：显示规则加载失败、围栏未匹配、雷达离线/检定异常、证据失败、重试和死信。

页面上的“确认”仅表示 AI 线索复核确认；不得显示为违法认定或案件办结。

## 9. 线索标识、去重和状态
- source_event_id 在同一命中片段内稳定；idempotency_key 在投递重试时不变。
- 同源键至少包含 task、track、rule、fence 和连续命中片段；跟踪 ID 只在 task 内解释。
- 同一线索事实或证据更新生成 event_revision，不重复创建主平台事件。
- 子项目状态严格为 generated/delivering/delivered/delivery_failed 和 reviewed_confirmed/reviewed_rejected。
- 跨无人机、卡口、警情和案件的合并，以及处罚状态，均由智慧交通主平台或法定系统负责。

## 10. 异常与降级
| 异常 | 处理 |
| --- | --- |
| 分类低置信/unknown | 仅保留待人工核验候选，不按货车规则输出高置信线索 |
| 无有效标定或运动补偿 | 暂停视频超速线索，禁止输出伪速度 |
| 围栏/规则缺失、过期或版本不符 | 暂停对应规则并告警；不得使用未知版本 |
| 路网服务断连 | 仅按批准策略使用最近已验证缓存并标记 stale，否则暂停空间规则 |
| 雷达离线或无检定信息 | 保留视频线索；雷达和融合字段为空并明确原因 |
| 雷达目标关联歧义 | 不融合，分别保留原始观测并进入人工复核 |
| 视频/雷达速度差异超限 | 不自动选择，输出差异和质量告警 |
| 证据帧、片段或哈希失败 | 标记 evidence_incomplete；不得显示为证据完整 |
| 证据存储空间不足 | 停止清理未到期证据，告警并按批准应急策略处理 |
| 主平台断连 | 持久化出站、指数退避、恢复重传；超限进入死信 |
| 规则配置错误 | 校验拦截并回退上一批准版本，记录审计 |

## 12. 标注与验收数据
- 货车/非货车验收集按高度、视角、昼夜、遮挡和目标尺度分层；只用于现有二分类质量基线，不作为新训练数据，也不建设货车细分类标注体系。
- 围栏集标注进入、离开、边界徘徊、停留、合规穿行、定位漂移和版本切换。
- 规则集由业务/法制给出正例、反例、例外车辆/时段和证据不足案例，并记录规则版本。
- 视频估速使用经确认参考设备或地面真值；雷达融合集保留时间、空间、方向、关联真值和检定状态。
- 同一连续轨迹不得跨训练/验证/验收集合泄漏；人工双标、争议仲裁和变更留痕。
- 样本量、允许误差、匹配窗、分层占比和通过阈值由 S4-TBD-005/007/010 冻结。

## 13. 分层验收与用例
### 13.1 验收指标
| 层级 | 指标 |
| --- | --- |
| 车辆二分类 | truck/non_truck Precision、Recall、混淆矩阵、unknown 率、单位小时误报 |
| 围栏/规则 | 进出时刻误差、围栏命中准确率、规则 Precision/Recall、例外排除正确率 |
| 视频估速 | MAE、P95 绝对误差、有效输出率、运动补偿降级正确率 |
| 雷达关联/融合 | 关联 Precision/Recall、误关联率、时间/空间残差、原始值完整率 |
| 证据 | 必填项完整率、哈希校验率、原件/副本关联率、审计覆盖率 |
| 集成/性能 | schema、幂等、回执、重试、死信、P95 延迟和持续运行 |
| 业务试点 | AI 线索确认率、驳回原因、自动取证率、复核耗时；不作为处罚率 |

### 13.2 核心验收用例
| 编号 | 场景与预期 |
