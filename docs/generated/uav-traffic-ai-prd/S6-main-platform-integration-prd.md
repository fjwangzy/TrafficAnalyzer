## 1. 目标、范围与责任边界

本分册建立“AI 生成 → 可靠上送 → 主平台回执 → 复核反馈 → 证据调阅”的可追溯闭环，使同一事件可幂等重放、可对账、可补偿且不静默丢失。

| 能力 | 无人机 AI 子项目 | 智慧交通主平台 |
| --- | --- | --- |
| 视频、遥测、标定、AI 计算 | 接入、同步、质量标记并生成结果 | 提供任务或基础接口条件 |
| 路网主数据 | 只读加载、缓存并携带权威 ID 与版本 | 维护路口、Link、车道、版本和代码表 |
| AI 事件 | 生成 `source_event_id`、幂等键、质量信息、证据引用 | 接收、分配/映射 `platform_event_id` |
| 去重合并 | 保证同源幂等，提供关联字段 | 负责跨无人机、卡口、警情的全局合并 |
| 业务处置 | 不建设、不镜像 | 负责研判、调度、派警、签收、到场、处置、升级、解除、归档 |
| 证据 | 生成原始材料、哈希、时间戳和不可变引用 | 授权调阅、案件关联与归档 |
| 反馈 | 接收并用于质量统计、样本闭环 | 回传 AI 结果确认/驳回及获准使用的处置结果 |

边界约束：本子项目仅保存投递状态和 AI 复核结果；主平台业务处置状态始终由主平台唯一维护，本文不定义也不复制其状态机。

## 4. 端到端流程与状态

### 4.1 状态模型

| 状态/结果 | 含义 | 允许后继 |
| --- | --- | --- |
| `generated` | 事件与证据引用已落持久化出站队列 | `delivering` |
| `delivering` | 已发起投递且等待确定性结果 | `delivered`、`delivery_failed` |
| `delivered` | 已保存有效接收回执和平台映射 | AI 复核结果可后续到达 |
| `delivery_failed` | 超过冻结的重试策略并进入死信 | 人工/自动恢复为 `delivering` |
| `reviewed_confirmed` | AI 识别结果被确认的质量标签 | 终态标签，可按更正流程修订 |
| `reviewed_rejected` | AI 识别结果被驳回的质量标签 | 终态标签，可按更正流程修订 |

`reviewed_*` 仅表示 AI 技术/业务复核，不表示警情确认、执法定案或处置完成；最终反馈枚举仍为【阻断 TBD】。

### 4.2 四类联动流程

| 流程 | 关键步骤与状态要求 |
| --- | --- |
| AI 事件上送 | 生成稳定 `source_event_id`/`idempotency_key`并冻结快照 → 校验 Schema、质量、路网和证据引用 → 在 `road9` 原子写入 `uav_ai_events` 与 `uav_event_outbox` → 投递时写 `uav_event_delivery_attempts`；重试复用原键、原事件和原发生时间，不可修复错误进入 `uav_dead_letters` 并告警。 |
| 接收回执 | 主平台鉴权、版本和幂等校验后，以来源事件或幂等键返回接收时间、结果及可用的 `platform_event_id`；子项目验源并原样留存，确定接收才置 `delivered`，未知结果先查询/对账，同键重复不得新增平台事件。 |
| 复核反馈 | 主平台按映射键回传 AI 确认/驳回、原因、时间、主体、反馈版本及获准摘要；子项目先写只增台账再更新独立复核结果，早到反馈待关联，低版本不覆盖高版本，冲突人工核对。 |
| 证据调阅 | 事件仅携元数据和不可变引用；主平台按授权接口申请，子项目校验主体、辖区、用途和关联后短期授权/流式返回，调阅方校验哈希、大小、类型；URL/API、时效、归档和脱敏均为【验收阻断】。 |

## 6. 业务规则

| 编号 | 规则 |
| --- | --- |
| S6-BR-001 | `source_event_id` 一经发布不可复用或改写。 |
| S6-BR-002 | 同一事件所有重试必须使用同一 `idempotency_key`。 |
| S6-BR-003 | 内容实质变化须按冻结的更正/新事件规则处理，不得借重试偷换 payload。 |
| S6-BR-004 | `platform_event_id` 由主平台分配或映射，子项目不得伪造。 |
| S6-BR-005 | 多个来源事件可能被主平台合并，故 `platform_event_id` 不默认在本地唯一。 |
| S6-BR-006 | 权威路网 ID 必须与 `road_data_version` 同存；未匹配时标记 `unmapped`。 |
| S6-BR-007 | 不得以本地数组序号或 `road_N` 冒充权威 Link/车道 ID。 |
| S6-BR-008 | AI `high/medium/low` 不直接等同于主平台 P1/P2/P3，映射须配置化。 |
| S6-BR-009 | 无有效回执不得把事件标为 `delivered`。 |
| S6-BR-010 | 未知投递结果优先查询或同键重放，禁止换键规避幂等。 |
| S6-BR-011 | 原始回执和反馈只增不改；派生状态可重算并保留变更审计。 |
| S6-BR-012 | 子项目不得保存或展示主平台派警处置状态副本。 |

## 7. 候选消息契约与边界

UAV 内部 canonical 契约固定为：`source_system=uav_traffic_analyzer_ai`；事件 Topic/类型为 `uav_ai_events` / `uav_ai_event`，反馈 Topic/类型为 `uav_ai_event_feedback` / `uav_ai_event_feedback`；内部 WebSocket channel 与数据库表同样遵守 `uav_` 前缀。智慧交通主平台若采用不同 URL、Topic 或名称，由集成边界适配器映射，不改变内部幂等键和来源标识。

以下是逻辑分层示例，不承诺主平台最终采用 JSON、HTTP 或 Kafka，也不承诺字段嵌套位置；最终外部 URL/Topic、类型和枚举均为【阻断 TBD】。

```json
{
  "envelope": {
    "message_id": "delivery-attempt-uuid",
    "source_system": "uav_traffic_analyzer_ai",
    "schema_version": "uav_ai_event/v1",
    "sent_at": "2026-07-13T10:00:01.000+08:00",
    "trace_id": "trace-uuid",
    "idempotency_key": "stable-retry-key"
  },
  "payload": {
    "source_event_id": "uav-ai-event-uuid",
    "event_type": "conflict",
    "occurred_at": "2026-07-13T10:00:00.123+08:00",
    "inter_id": "authoritative-inter-id",
    "road_data_version": "published-version-id",
    "quality_status": "ok",
    "evidence_refs": []
  }
}
```

| 边界 | 字段职责 |
| --- | --- |
| Envelope | 传输标识、来源、契约版本、发送时间、追踪和幂等；不放大证据或业务处置状态。 |
| Common payload | `source_event_id`、`event_type`、`occurred_at`、`intersection_id/inter_id`、路网版本、地图匹配、位置、严重度、置信度、质量和证据引用。 |
| Extension payload | 冲突/换道、测绘、执法线索等类型专属指标；按 `event_type + schema_version` 校验。 |
| Ack payload | 关联键、接收结果、平台接收时间、`platform_event_id`、原因/错误；最终枚举待冻结。 |
| Feedback payload | 映射键、复核结果、原因、时间、主体、反馈版本及获准范围；最终枚举待冻结。 |

## 8. 幂等、可靠性与兼容

映射台账以 `source_system + source_event_id` 和 `idempotency_key` 建唯一约束。`uav_ai_events` 保存源事件，`uav_event_outbox` 保存待投递快照及状态，`uav_event_delivery_attempts` 只增记录每次尝试/回执，`uav_event_feedback` 保存复核反馈，`uav_dead_letters` 保存耗尽或不可修复项；共同保留 payload 哈希、平台映射和状态历史。幂等保留时长为【阻断 TBD】。

| 场景 | 处理要求 |
| --- | --- |
| 连接失败/超时 | 标记结果未知，指数退避加抖动；先查询或同键重放。 |
| 鉴权/授权失败 | 默认不可重试，立即告警并隔离；凭据恢复后经审批重放。 |
| Schema/枚举不兼容 | 不重试原载荷；进入隔离区，完成版本修复后补偿。 |
| 限流/平台暂不可用 | 尊重平台重试提示；无提示时按冻结策略退避。 |
| 明确业务拒绝 | 保存原因；仅可修复数据问题时走受审计补偿流程。 |
| 重试耗尽 | 转死信、告警、分派责任人，禁止静默丢弃。 |

重试基数、倍率、最大间隔、最大次数、超时阈值及死信响应 SLA 均未冻结，属于【验收阻断】；实现必须参数化并记录每次决策原因。

乱序处理按“反馈版本/顺序号 → 平台时间 → 本地接收时间”候选优先级执行；最终排序规则由双方冻结。无法判断新旧时保留双方版本并告警，不做猜测性覆盖。

兼容策略：生产者显式发送 `schema_version`；消费者只接受支持矩阵内版本；新增可选字段应向后兼容，删除/改义/改类型必须升大版本；兼容窗口和退役通知期为【阻断 TBD】。

对账至少比较本地已生成数、尝试数、已接收数、平台映射数、复核反馈数和死信数。平台查询/清单接口未定时不得宣称已具备自动对账。

补偿仅允许：原键重放、补拉回执、补拉反馈、重新签发证据授权、修复映射；每次补偿记录发起人、原因、前后值、批次和结果，禁止直接改原始台账。

## 9. 安全与审计

1. 链路必须加密，服务身份采用最小权限；mTLS、OAuth2 或签名方案尚未确定，为【阻断 TBD】。
2. 密钥、Token、签名和证据访问参数不得写日志；凭据须支持轮换、吊销和环境隔离。
3. 证据默认私有，不得发送永久公开 URL；授权应绑定事件、主体、用途和有效期。
4. 事件与证据保留期限、跨域传输、脱敏和下载限制由业务/法制/网安冻结。
5. 审计覆盖发送、回执、反馈、调阅、下载、重放、补偿、配置和权限变更，并防篡改。
6. 审计查询须能按 trace、来源事件、平台事件、操作者和时间范围关联，不暴露无权数据。

## 10. 联调监控页面

页面面向运维、质量和审计角色，默认脱敏并按辖区/环境隔离。

| 区域 | 必备内容 |
| --- | --- |
| 总览 | `generated/delivering/delivered/delivery_failed`、成功率、P50/P95/P99、重试/死信、反馈覆盖率。 |
| 趋势 | 按事件类型、主平台端点、Schema、模型版本、路口和时间展示延迟与失败趋势。 |
| 队列 | 出站积压、最老消息龄、重试分布、死信原因和责任人。 |
| 事件详情 | 脱敏 envelope/payload、哈希、尝试历史、回执、映射、反馈、证据元数据。 |
| 对账 | 双方计数、差异类型、补偿批次、处理进度和未解决项。 |
| 操作 | 授权角色可执行原键重放/隔离/补偿；二次确认且全量审计，不可编辑原 payload。 |

告警至少覆盖持续失败、成功率突降、P95 恶化、积压/消息龄越界、死信新增、认证失败、Schema 拒绝、对账差异和反馈长期缺失；阈值待 SLA 冻结。

## 11. 异常处理

| 异常 | 期望行为 |
| --- | --- |
| `road_context_status=stale/missing/version_mismatch` | 依冻结规则拒绝或降级上送，保留质量标记，不伪造主数据。 |
| 证据尚未就绪 | 事件与证据分离；按契约标记待就绪并后补，不阻塞已允许的事件上送。 |
| 回执丢失但平台已接收 | 查询或同键重放，取得同一映射后收敛。 |
| 反馈无法关联 | 写待关联区并告警，补齐映射后自动重放关联。 |
| 证据过期/哈希不符 | 拒绝调阅或下载，记录审计并按授权流程重新签发/修复。 |
| 平台合并事件 | 保留来源到平台的多对一映射，不反写或删除原 AI 事件。 |

| P2 可靠性 | 重复、超时、断网、限流、进程重启、死信恢复 | 无重复事件、无静默丢失 |
| P3 兼容与乱序 | 双版本、未知字段、不兼容版本、反馈早到/更正 | 按支持矩阵处理且不误覆盖 |
| P4 安全与性能 | 鉴权失败、越权调阅、密钥轮换、容量和延迟 | 网安通过，冻结 SLA 达标 |
| P5 试运行 | 真实路口灰度、日对账、告警值守、问题闭环 | 连续周期无未解释差异；周期【TBD】 |
