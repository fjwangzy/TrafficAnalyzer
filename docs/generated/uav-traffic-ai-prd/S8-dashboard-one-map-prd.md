## 1. 分册目标与边界

### 1.1 产品目标

建设以城市地图为背景的无人机交通 AI 工作台首屏，使交通指挥中心主任进入系统后，先看全局、再抓重点、处理平台内待办、最后下钻核验，在一张图上快速回答六个问题：

1. **全局态势怎么样**：当前项目覆盖范围内整体平稳、趋紧还是存在突出风险，较上一可比时段是在改善还是恶化。
2. **哪里最需要关注**：哪些路口出现持续拥堵、冲突、执法线索或监测异常，影响等级、持续时间和变化趋势如何。
3. **风险是否正在扩大**：重点事件是单点、持续还是多点扩散，是否存在同辖区或相邻路口集中出现的趋势。
4. **无人机保障是否到位**：应监路口、正在监测路口、在线无人机、执行任务和监测降级之间是否存在保障缺口。
5. **结论是否可信**：数据是否新鲜、覆盖是否完整、坐标/路网版本是否有效，是否需要先核验再下钻。
6. **平台内有什么待办**：哪些 AI 技术复核、测绘交付、集成重放或配置核验需要当前用户处理；不得混入主平台派警、处置和结案任务。

主任使用目标为“5 秒辨识全局状态、30 秒锁定重点路口和关键待办、1 分钟进入证据或专业页面核验”。目标不是堆叠全部模块，而是形成“全局态势 → 重点关注 → 平台待办 → 保障核验 → 专业下钻”的首屏决策中枢。地图在首屏有效内容区占主导，建议不低于 65%，最终布局比例由视觉稿和目标分辨率评审冻结。

### 1.2 业务价值

- 主任无需在 Dashboard、GIS、无人机、告警和实时监测页面之间来回切换即可掌握项目全局、突出问题和保障缺口。
- 用权威 `inter_id + road_data_version` 把无人机、任务、管道、路口态势和 AI 事件归并到同一空间对象。
- 将“未纳管、已纳管、正在监测、监测降级、离线”和“正常、拥堵、风险事件”分开表达，避免把设备故障误认为道路正常。
- 用持续时间、变化方向和数据可信度解释“为什么需要关注”，不让主任依赖不透明的单一总分。
- 为值守、演示、试点复盘和验收提供一致的项目级入口，但业务处置仍在智慧交通主平台闭环。

### 1.3 范围边界

本期包含：

- 城市底图、项目覆盖范围、权威路口点位及按缩放级别显示的 Link/车道图层；
- 无人机监控覆盖、当前监测状态、无人机位置和任务/管道健康概览；
- 项目级 KPI、路口风险/拥堵概览、实时 AI 事件、数据质量和新鲜度；
- 平台内可执行待办摘要，包括 AI 技术复核、测绘交付、集成重放和配置核验；
- 地图筛选、图层控制、路口选中详情和到实时监测、AI 事件、无人机、GIS 复盘页面的深链；
- 全屏值守、断线降级、权限过滤、空态和数据口径说明。

本期不包含：

- 不建设智慧交通主平台已有的全市警情、派警、处置、解除、案件归档和跨系统一张图；
- 不在首屏执行信号配时、航线规划、多无人机自动调度、执法定案或事故测绘编辑；
- 不复制权威路网底库，不在浏览器端修正路口、Link 或车道主数据；
- 不扩展货车细分类，首屏只展示现有模型可提供的货车/非货车结果或相关事件；
- 不以 Grafana 作为首屏或嵌入其面板，不从 InfluxDB 读取目标态指标；
- 不把热区聚类、未来轨迹或概率推演包装为已发生事实。

## 2. 用户、场景与价值

| 角色 | 首屏核心任务 | 需要看到 | 允许操作 |
| --- | --- | --- | --- |
| 交通指挥中心主任 | 快速掌握全局态势、突出风险、变化趋势和保障缺口 | 总体状态、重点关注榜、空间分布、趋势、无人机保障和可信度 | 切换范围/时段、锁定重点、下钻核验、打开主平台 |
| 值班指挥员 | 持续关注重点路口和新发事件，辅助主任核验 | 覆盖、在监、拥堵、事件、视频入口和数据新鲜度 | 筛选、选点、查看详情、跳转专业页面 |
| 交通工程/分析人员 | 比较路口与时段，识别异常数据 | 流量、拥堵、转向摘要、质量和路网版本 | 筛选、查询、跳转报告/GIS 复盘 |
| 无人机操作/运维人员 | 定位无人机、任务、管道和链路异常 | 飞行/悬停、任务、管道、遥测和数据延迟 | 跳转无人机或系统管理；无派警权限 |
| 测试/监理 | 验证一图口径和数据一致性 | 数据来源、窗口、时间、质量、版本和降级状态 | 按用例查询、导出验收证据【待确认】 |
| 智慧交通主平台用户 | 从大项目进入本子项目查看 AI 详情 | 项目级无人机 AI 能力与来源事件 | 单点登录和深链【外部依赖】 |

典型场景：早晚高峰值守、重点路口临时布控、重大活动保障、系统交接班、无人机/管道故障定位、AI 事件集中出现、路网版本切换、主平台短时不可用和试点验收演示。

### 2.1 主任决策模型

首屏按照主任的判断顺序组织，而不是按照后端系统模块组织：

| 判断层级 | 主任关心的问题 | 首屏回答方式 | 下钻去向 |
| --- | --- | --- | --- |
| 全局 | 全市/辖区项目态势是否平稳 | 地图总体分布、重点指标、较上一可比时段变化 | 辖区筛选或轨迹研判 |
| 重点 | 当前最突出的是哪些路口和事件 | 重点关注榜、地图高亮、持续时间和风险构成 | 路口实时监测/AI 事件 |
| 趋势 | 风险在缓解、持续还是扩大 | 最近 15/30/60 分钟变化、相邻点集中和新增/升级数量 | GIS 复盘/趋势报告 |
| 待办 | 当前用户需要在本平台完成什么 | AI 复核、测绘交付、集成重放、配置核验及等待时长 | 对应工作台或详情页 |
| 保障 | 无人机和监测能力是否覆盖重点 | 应监、在监、降级、在线无人机和任务缺口 | 无人机/系统管理 |
| 可信 | 这些结论是否足以支持研判 | 数据新鲜度、coverage、质量、路网版本和异常来源 | 数据质量/系统详情 |

首屏不得把 GPU、CPU、Kafka Topic、消费者数量等技术指标作为主任级核心 KPI。技术指标只以“系统正常/部分降级/不可用”的摘要进入顶部状态，详细数据下沉到系统管理页面。

## 3. 当前基线与主要差距

### 3.1 当前实现基线

- `/` 当前提供活跃路口、总流量、拥堵指数、未处理告警、24 小时趋势、系统状态、路口列表和最近告警。
- 当前 24 小时趋势查询硬编码 `INT_camera_1`，不能代表项目级或用户当前选择范围。
- `/gis` 已能查询路口、历史轨迹和历史冲突，但路口标记按数组序号计算屏幕位置，背景为网格，不是按 `center_lat/center_lon` 落到真实城市底图。
- 当前前端仍订阅遗留 `alerts/system` 等通道；目标迁移后应使用 `uav_alerts/uav_system` 等 canonical 名称。

### 3.2 目标差距

| 差距 | 影响 | 本分册要求 |
| --- | --- | --- |
| 首页不是地图主导 | 无法一眼理解覆盖空间和重点位置 | `/` 改为城市地图主画布 |
| GIS 标记不使用真实坐标 | 容易把示意位置误认为真实路口 | 使用经校验的权威坐标和真实底图 |
| “活跃”定义不清 | 管道运行、无人机在线和正在监测容易混用 | 拆分覆盖、监测、健康、风险四类状态 |
| 趋势硬编码单一路口 | 项目 KPI 失真 | 按当前权限范围/筛选范围聚合，禁止默认硬编码 |
| 首页与 GIS 职责重叠 | 导航和开发边界不清 | 首页做项目概览，`/gis` 做轨迹研判和轨迹/冲突深钻 |
| 全局实时数据策略未定义 | 大量路口逐一订阅可能压垮浏览器和服务 | 全局摘要 REST/聚合推送，选中路口再订阅明细 |

## 4. 核心概念与状态模型

### 4.1 口径定义

| 概念 | 候选定义 | 禁止混用 |
| --- | --- | --- |
| 项目路口 | 当前用户权限范围内，已纳入无人机 AI 项目清单且可关联权威 `inter_id` 的路口 | 不等于城市权威路口总数 |
| 具备监控条件 | 已完成有效设备/任务绑定、路网上下文和最低标定/视频源配置的项目路口 | 不等于当前正在监测 |
| 正在监测 | 在新鲜度窗口内同时存在有效任务、运行管道和有效态势数据的路口 | 不得只凭无人机在线或管道状态判定 |
| 监测降级 | 任务仍在执行，但视频、遥测、标定、路网或消息链路至少一项低于质量门槛 | 不得显示为“正常监测” |
| 在线无人机 | 在遥测新鲜度窗口内上报且设备状态可用的无人机 | 不等于已绑定路口或正在执行任务 |
| 本地 AI 事件 | UAV 子项目生成的拥堵、冲突、执法线索、测绘结果等事件 | 不等于主平台警情或已处置事件 |

上述定义的时间窗口、有效状态组合和分母范围由 S8-TBD-001/S8-TBD-005 冻结。页面及 API 禁止继续使用没有口径说明的单一 `active` 字段作为全部状态结论。

### 4.2 路口四维状态

每个项目路口同时具有四个独立维度：

| 维度 | 枚举候选 | 表达要求 |
| --- | --- | --- |
| 项目覆盖 | `managed/configurable/unconfigured` | 是否纳入项目及是否具备最低配置 |
| 监测运行 | `monitoring/standby/degraded/offline/unknown` | 用点位外环、图标或标签表达，不与风险颜色混用 |
| 交通风险 | `critical/warning/attention/normal/unknown` | 来自时窗内有效 AI 事件和拥堵规则；显示事件类型与时间 |
| 数据质量 | `verified/degraded/stale/missing` | 必须显示质量标识和最后更新时间；低质量不得伪装成道路正常 |

同一路口可同时为“正在监测 + 高风险”或“离线 + 风险未知”。系统不可因没有收到事件就把离线/缺数据路口判为正常。

### 4.3 优先级与聚合原则

1. 地图点位默认以**交通风险**决定关注优先级，以**监测运行状态**和**数据质量**作为独立辅标。
2. 同一统计窗口存在多个事件时，展示最高有效风险等级，并显示事件数量和构成；不得把本地等级直接映射为主平台警情等级。
3. 数据过期或缺失时，风险显示为 `unknown`，保留最近有效值的时间，不继续维持“正常”绿色。
4. 一个路口绑定多架无人机时，路口监测状态按有效任务聚合，详情中逐架展示；不得用任意一架在线覆盖其他故障。

## 5. 前置条件、输入与输出

### 5.1 前置条件

1. `road9` 内权威路网 schema/只读视图、路口坐标字段、SRID/GCJ02 语义和 `road_data_version` 已由 S5 冻结。
2. 城市底图供应商、授权范围、坐标系、瓦片部署和离线策略已批准。
3. 项目路口清单、辖区/项目范围、设备—路口—任务绑定和用户数据权限可查询；S9 的 Drone、FlightPlan、Mission 和 Pipeline 状态边界已冻结。
4. `uav_traffic_metrics`、`uav_telemetry_metrics`、`uav_system_metrics`、`uav_alerts`、`uav_drones`、`uav_flight_plans`、`uav_missions`、管道状态及必要的 AI 事件已迁移到 `road9` 目标结构。
5. Dashboard 聚合 API、缓存、WebSocket 补推和数据新鲜度口径已完成契约测试。

### 5.2 输入

| 数据域 | 主要字段 | 权威来源/边界 |
| --- | --- | --- |
| 项目与权限 | project/scope/region、授权 `inter_id` 集合 | 智慧交通主平台/统一身份【待确认】 |
| 路网与路口 | `inter_id`、名称、坐标、辖区、Link/车道、`road_data_version` | `road9` 权威只读视图或批准 API；UAV 只引用 |
| 设备与任务 | drone/camera/mission/pipeline、绑定、期望/实际状态 | `uav_` 平台状态表与运行缓存 |
| 实时态势 | 流量、速度、排队、拥堵、方向、coverage、质量 | `uav_traffic_metrics` TimescaleDB Hypertable |
| 遥测 | 位置、电量、高度、速度、悬停、定位质量、时间 | `uav_telemetry_metrics` |
| AI 事件/告警 | 类型、严重度、状态、时间、位置、证据引用 | `uav_ai_events`、`uav_conflict_events`、`uav_alerts`；不复制主平台处置状态 |
| 系统健康 | 管道、GPU/CPU、消息积压、延迟、coverage/drop | `uav_system_metrics` |

### 5.3 输出

- 项目级 KPI 快照及其统计范围、窗口、时间和质量；
- 当前视野/筛选范围内的路口地图点位、聚合簇、覆盖/监测/风险/质量状态；
- 无人机位置和任务摘要，必要时显示最近有效位置而非伪装实时位置；
- 选中路口详情、实时事件列表和到专业页面的带参深链；
- 可审计的页面查询/导出元数据【是否导出待确认】，不新增第二套业务事实。

## 6. 首屏信息架构

| 区域 | 目标内容 | 交互与约束 |
| --- | --- | --- |
| 顶部项目栏 | 项目名称、当前辖区/范围、系统时间、总体态势、整体可信度、系统健康摘要、全屏入口 | 主任先看到态势和可信度；技术明细下沉，不得只显示装饰性标题 |
| 主任核心指标 | 监测覆盖、重点风险路口、重度拥堵、无人机保障、较上一可比时段变化 | 建议 4～5 项；每项可解释分子、分母、窗口、趋势和质量 |
| 城市地图主画布 | 底图、项目覆盖、路口、无人机、事件/风险、按需 Link/车道 | 占首屏主导；真实坐标；支持聚合、缩放、平移、复位 |
| 筛选/图层区 | 辖区、监测状态、风险、事件类型、质量、时间窗口、图层开关 | 筛选结果同步 KPI、地图和事件栏；支持一键清空 |
| 重点关注榜 | 最高风险、持续拥堵、新增/升级事件、风险集中和保障缺口 | 默认不超过 10 项；按可解释规则排序，显示原因、持续时间和变化方向 |
| 待办任务 | AI 技术复核、测绘交付、集成重放、配置核验 | 按权限过滤并显示数量、最老等待时长和目标工作台；不承载主平台处置任务 |
| 路口详情抽屉 | 路口、路网版本、任务/无人机/管道、态势、事件、质量 | 不遮蔽全部地图；提供专业页面深链，不在此完成派警 |
| 变化摘要/状态栏 | 新增、升级、缓解、降级数量；四维状态图例、数据时间、连接状态 | 支持交接班和主任快速判断趋势；颜色不是唯一编码 |

| `/` | 工作台首屏、城市地图态势纵览、项目 KPI、待办任务、重点定位和跨模块入口 | 轨迹逐点复盘、规则配置、派警处置 |
| `/monitoring?intersection_id=...` | 单路口实时视频、BEV、车道指标和事件回放 | 全市项目总览 |
| `/gis?intersection_id=...` | 路口空间详情、历史轨迹、冲突和热区复盘 | 首页值守总览 |
| `/events?...` | AI 事件筛选、技术复核和推送状态 | 主平台警情处置 |
| `/drones?drone_id=...` | 无人机详情、遥测、任务和轨迹 | 路口交通态势判定 |

导航名称与边界已冻结：`/` 为“工作台首屏”，`/gis` 为“轨迹研判”，`/events` 为“AI 事件中心”；旧 `/alerts`、`/video`、`/risk-hotspots` 等深链使用兼容跳转，不再作为正式菜单。工作台与实时监测统一采用“左侧六个一级业务域 + 顶部当前域二级页面”的共享壳层；进入全域态势时，顶部只显示“工作台首屏 / 实时监测 / 轨迹研判”。

### 6.2 主任首屏信息优先级

| 优先级 | 信息 | 首屏策略 |
| --- | --- | --- |
| P0-1 | 新发/升级的高风险事件、持续重度拥堵 | 始终可见，地图和关注榜联动；低质量时明确提示“待核验” |
| P0-2 | 当前监测覆盖及重点路口保障缺口 | 顶部指标 + 地图状态；可一键筛选降级/离线路口 |
| P0-3 | 风险变化趋势与空间集中 | 显示改善/持平/恶化及新增/升级/缓解数量，不只显示静态总数 |
| P0-4 | 数据可信度和整体系统健康 | 以简洁状态进入顶部，异常时可展开来源；正常时不占据大量空间 |
| P1 | 项目规模、总流量、一般事件、无人机明细 | 作为辅助指标、筛选结果或详情展示 |
| P2 | GPU、CPU、Topic、进程日志、模型版本明细 | 下沉系统管理，不进入主任首屏核心区 |

“总体态势”可以使用文字状态和构成说明，但在 S8-TBD-004/005 关闭前不得生成缺乏批准公式的“全市综合分”或单一红黄绿结论。

## 7. 业务主流程

1. 用户登录后，系统从统一身份/主平台取得角色、辖区和项目数据范围。
2. 首屏加载地图配置、项目范围、路网版本和静态路口点位；坐标或底图未通过校验时禁止展示为真实一图。
3. 聚合 API 返回同一 `as_of` 快照下的主任核心指标、重点关注榜、平台内待办摘要、变化摘要、路口摘要、无人机保障摘要和质量信息。
4. 页面按权限与筛选条件计算当前可见集合；服务端为统计真源，前端只做展示级筛选，不重新发明业务口径。
5. 页面订阅 `uav_alerts` 和 `uav_system` 更新全局事件/健康；只在用户选中路口时订阅 `uav_intersection:{intersection_id}`，选择关联无人机时再订阅 `uav_telemetry:{drone_id}`。
6. 主任点击关注项或路口后，地图定位并打开详情抽屉；详情先解释“为何关注、持续多久、是否升级、数据是否可信”，再展示技术来源和专业页面入口。
7. 用户选择“实时监测/事件详情/无人机详情/GIS 复盘”后，携带稳定 ID 和筛选上下文跳转。
8. WebSocket 断线或页面恢复时，以 REST 快照补齐事件和状态，再继续增量更新，避免仅靠瞬时推送形成真源。

## 9. 业务规则与统计口径

| 编号 | 规则 |
| --- | --- |
| S8-BR-001 | KPI 分母默认为当前用户可见的“项目路口”，不得用城市全部权威路口数替代；分母和筛选范围必须可见。 |
| S8-BR-002 | “正在监测”必须同时满足有效任务、运行管道、路口绑定和新鲜态势数据；任一缺失时按规则进入 `standby/degraded/offline/unknown`，不得只凭 `pipeline=running`。 |
| S8-BR-003 | “在线无人机”由遥测新鲜度和设备状态共同判定；只存在静态设备记录不能计为在线。 |
| S8-BR-004 | 地图点位必须来自已确认的 `inter_id + road_data_version`；无法验证坐标时进入隔离/列表降级，不按序号生成位置。 |
| S8-BR-005 | 路口风险等级只聚合窗口内、质量达标且未失效的本地 AI 事件；本地风险不得直接等同主平台警情等级。 |
| S8-BR-006 | 数据 `stale/missing` 时风险为 `unknown`；最近有效数据可灰显并标注时间，但不得继续显示实时绿态。 |
| S8-BR-007 | KPI、地图和事件列表必须共享同一筛选条件及可比较的 `as_of/window_start/window_end`；不同时间窗口不得无提示混排。 |
| S8-BR-008 | coverage 低于 S7/S8 冻结门槛的时间桶不参与完整 KPI；页面显示缺口和原因。 |
| S8-BR-009 | 同一告警经全局和路口 WebSocket 重复到达时按事件/告警稳定 ID 去重，等级升级或状态更新按版本覆盖。 |
| S8-BR-010 | 多无人机覆盖同一路口时，路口 KPI 去重计一次；无人机 KPI 按设备去重，详情保留逐设备状态。 |
| S8-BR-011 | 聚合簇显示当前筛选范围内的路口数量及最高风险/异常计数，不把聚合簇本身当作事件。 |
| S8-BR-012 | 货车相关显示保持货车/非货车二分类，不展示无法由当前模型支持的重/中/轻型货车细分。 |
| S8-BR-013 | 重点关注榜必须输出入榜原因、规则/窗口、持续时间、变化方向和质量；不得仅输出不可解释的 AI 总分。 |
| S8-BR-014 | 上一可比时段须使用相同辖区、项目路口集合、指标口径和可比较的数据覆盖；任一不一致时不得显示虚假的上升/下降百分比。 |
| S8-BR-015 | 系统技术故障只有在影响监测覆盖、数据可信度或重点路口保障时进入主任关注榜；其他技术明细留在系统管理。 |

### 9.1 KPI 候选目录

| KPI | 候选口径 | 展示要求 |
| --- | --- | --- |
| 监测覆盖 | 正在监测路口 / 当前应监或具备监控条件路口【分母待冻结】 | 同时显示降级/离线缺口和变化 |
| 重点风险路口 | 当前窗口内存在批准等级风险的去重路口数 | 显示新增、升级、持续、缓解构成 |
| 重度拥堵路口 | 当前窗口内拥堵指数超过批准阈值的去重路口数 | 显示持续时间、趋势和数据覆盖 |
| 无人机保障 | 执行任务且遥测有效的无人机 / 计划保障资源【分母待冻结】 | 显示任务中、待命、异常和保障缺口 |
| 数据可信度 | 满足 freshness、coverage、路网/坐标和链路质量的路口占比【候选】 | 必须拆解缺失原因，不能替代逐项质量 |
| 项目路口 | 当前权限和项目范围内去重 `inter_id` 数 | 作为规模辅助值，显示范围/版本 |
| 重点 AI 事件 | 当前窗口内达到批准等级且质量有效的去重事件数 | 作为事件辅助值，显示类型和技术确认状态 |

最终 KPI 数量、名称、阈值和窗口由 S8-TBD-001/S8-TBD-005 冻结；首屏不得为了“丰富”展示无法解释或重复的指标。

## 10. 数据、接口与实时更新

### 10.1 Dashboard 读模型

首屏是现有业务事实的只读聚合，不新增独立业务真源。默认从 `road9` 中的权威路网只读对象、`uav_*` 普通表和 TimescaleDB Hypertable 聚合；若为性能建设连续聚合、物化视图或缓存，其名称须遵守 `uav_` 前缀并可从事实重建，不得形成第二套事件或处置状态。

### 10.2 REST API 候选

以下路径是 S8 评审候选，不视为已冻结实现；API 路径不属于“消息和数据库表必须以 `uav_` 开头”的约束范围，但响应中的消息/事件类型仍遵守 canonical 契约。

| 方法与候选路径 | 用途 | 关键约束 |
| --- | --- | --- |
| `GET /api/v1/dashboard/overview` | 返回主任核心指标、变化摘要、重点关注榜、整体健康和统一 `as_of` | 支持 scope/region/time_window/compare_window；返回口径、入榜原因和质量 |
| `GET /api/v1/dashboard/intersections` | 按 bbox/zoom/filter 返回路口地图摘要或聚合簇 | 服务端权限过滤、分页/瓦片化、版本一致 |
| `GET /api/v1/dashboard/intersections/{inter_id}` | 返回选中路口任务、无人机、管道、态势、事件和质量 | 不返回无权证据；ID 与版本明确 |
| `GET /api/v1/dashboard/drones` | 按 bbox/任务返回无人机摘要 | 位置新鲜度、定位质量和脱敏策略 |
| `GET /api/v1/dashboard/legend` | 返回状态枚举、阈值版本和展示说明【候选】 | 也可随 overview 返回，避免独立请求 |

overview 响应至少包含：`project_scope`、`road_data_version`、`as_of`、`window_start/window_end`、可比较基准窗口、`data_quality`、`coverage_ratio`、KPI 值及分子分母、变化方向、状态计数、重点关注项及入榜原因、事件摘要和 `schema_version`。精确字段、分页、bbox 坐标和错误码由 S8-TBD-006 冻结并同步 `docs/API_CONTRACTS.md`。

### 10.3 WebSocket 策略

- 全局默认订阅：`uav_alerts`、`uav_system`。
- 选中路口后订阅：`uav_intersection:{intersection_id}`；切换路口时退订旧频道。
- 需要无人机实时详情时订阅：`uav_telemetry:{drone_id}`；关闭详情后退订。
- 禁止为城市全部路口同时建立明细订阅。若后续需要全局路口状态增量，须新增经过容量评审的 `uav_` channel/type，并在 API 契约中冻结，不得复用不相干消息。
- WebSocket 只提供增量体验；首次加载、断线恢复和审计查询以 REST/数据库事实为准。

## 11. 页面交互与显示规则

### 11.1 默认状态

1. 默认视野为当前用户权限范围/试点城市项目边界，中心点和缩放级别由项目配置提供，不写死在前端。
2. 默认展示项目路口、监测状态、重点风险和无人机保障；Link/车道等高密度图层默认关闭或按缩放门槛加载。
3. 默认时间窗口为“当前实时窗口”，具体时长待冻结；页面明确显示 `as_of` 和连接状态。
4. 没有任何项目路口时展示配置指引和责任方，不显示全零 KPI 冒充系统正常。
5. 技术健康正常时只显示简洁状态；部分降级或不可用时展开影响范围、持续时间和受影响重点路口，不用 GPU 百分比抢占主任注意力。

### 11.2 路口选择

- 点击点位或事件：地图居中/适度缩放，打开同一路口详情，不重置用户筛选。
- 点击聚合簇：优先缩放展开；达到最大缩放仍重叠时展示路口列表。
- 详情中所有指标显示单位、窗口、最后时间和质量；无数据用“无数据/已过期/无权限”区分，不统一显示 `0`。
- 深链携带 `intersection_id/inter_id`、必要的 `event_id/drone_id` 和时间窗口；目标页再次进行权限校验。

### 11.3 视觉编码原则

- 风险等级和监测运行状态使用不同视觉通道，例如风险使用填充/徽标，运行状态使用外环/图标；最终方案由视觉稿冻结。
- `critical/warning/normal/unknown` 不只靠红黄绿区分，配套文字、图标或形状。
- 过期数据统一灰显并显示“数据截至 HH:mm:ss”；最近有效位置使用轨迹尾点或虚线状态，不冒充实时。
- 地图图例与页面状态必须保持一致，阈值或枚举升级时随 `schema_version/rule_version` 更新。

## 12. 异常、降级与人工兜底

| 异常 | 页面行为 | 兜底/责任 |
| --- | --- | --- |
| 底图服务失败 | 保留列表、KPI和事件栏；地图区明确不可用，不显示网格伪地图 | GIS/运维检查瓦片、授权和网络 |
| 路口坐标/SRID 未确认 | 隔离异常点位并显示数量；禁止随机摆点 | 数据/GIS 修复权威数据 |
| 路网版本不一致 | 停止跨版本聚合或分组展示，标记 `version_mismatch` | S5 快照回滚/修复 |
| overview 部分来源超时 | 返回部分结果及每域状态，不把缺失域计为 0 | 平台按域降级并告警 |
| WebSocket 断线 | 显示断线/重连，周期 REST 回补；恢复后按 ID/版本去重 | 平台/前端 |
| 态势数据过期 | 点位状态转 `stale/unknown`，保留最后时间 | 运维定位管道/消息/数据库 |
| 无人机遥测过期 | 不移动标记，灰显最近位置并显示时间 | 无人机运维 |
| 用户无地图/证据权限 | 隐藏受限图层/字段并解释权限边界 | 统一身份/网安 |
| 路口数量超容量 | 聚合、bbox 分片或服务端瓦片化；不得一次返回/渲染全量车道 | 架构/前端性能治理 |
| 主平台不可用 | UAV 首屏保持只读监控；外部处置深链禁用并告警 | S6 可靠投递与恢复 |

## 13. 非功能、安全与可运维性

| 编号 | 要求 |
| --- | --- |
| S8-NFR-001 | 首屏地图、核心 KPI 和连接状态的 P50/P95 可交互时间由目标网络、设备和路口规模压测冻结；候选目标为常规内网 P95 ≤ 5 秒。 |
| S8-NFR-002 | overview、地图点位和详情 API 分别定义 P95、超时、缓存和最大返回量；任何缓存响应带 `as_of` 和质量。 |
| S8-NFR-003 | 支持 `road9` 实际项目路口规模，并以历史调查约 8,335 个路口作为容量参考而非目标事实；点位聚合和 bbox 查询必须压测。 |
| S8-NFR-004 | 实时更新延迟、数据新鲜度和 REST 回补周期须可观测；页面不得静默停止更新。 |
| S8-NFR-005 | 用户只能看到授权辖区、路口、无人机、事件和证据摘要；服务端强制鉴权，前端隐藏不是安全控制。 |
| S8-NFR-006 | 坐标、飞行轨迹和证据按网安要求脱敏/限权；日志不得记录 Token、密钥或未授权证据 URL。 |
| S8-NFR-007 | 支持键盘操作、焦点可见、文本缩放和非颜色状态辨识；地图关键结论须有列表等价入口。 |
| S8-NFR-008 | 支持目标大屏和办公终端分辨率；最小分辨率、全屏轮播和触控需求待 S8-TBD-008 冻结。 |
| S8-NFR-009 | 页面错误、筛选、加载、地图图层和深链操作形成 `uav_` 规范的观测指标；指标写入 `uav_system_metrics`，不新增 Grafana/InfluxDB 链路。 |
| S8-NFR-010 | 聚合查询不得逐帧访问权威路网库；路网使用批准快照/只读服务，时序指标查询使用 TimescaleDB 索引/连续聚合。 |
| S8-NFR-011 | 重点关注榜和变化摘要在同一输入快照下结果确定、可复算；规则版本、入榜原因和质量可审计。 |

任何时候都不得以当前网格示意位置作为真实城市地图验收，不得以“有点位/有颜色”替代状态口径验收，也不得因首屏显示主平台相关信息而把 AI 子项目扩展为业务处置系统。
