## 2. ADR-025 实现与合同调整

- 本地回放目录保存视频/遥测 SHA-256、大小、录制时间、时长、帧数、帧率、期望速度和偏移；
  注册幂等且保留既有地图回放目录边界。
- ByteTrack 成熟关联立即得到稳定 `track_id` 并保留 `association_id`；地理质量和路网匹配不再结束、
  丢弃或拆分轨迹。候选只表示尚未满足最短时长和点数的关联。
- 能力拆为 trajectory/geo/road/TCC 四层；`formal_analytics_eligible` 仅保留为完整道路能力兼容字段，
  不再控制 `TrackerInfoUpdateNode` 缓冲和 `uav_track_complete/v1`。
- `uav_track_complete/v1` 强制像素、时间、帧号和可空 ENU/GCJ-02 等长；无地理能力时速度为空。
  路网只填充 Lane ID、Link ID 与匹配质量；世界坐标、速度、方向、Movement、统计和 TCC 不读取路网门禁。
- 新增 checksum 保护的 SourceGeoRegistration。Mission/Pipeline 独立固定 verified 配准；地图 Bundle
  可选，旧 Bundle 中精确命中的 verified 配准继续兼容。
- 运行时回归明确覆盖 `geo=true / road=false`：active 与自然 EOF 完成事件继续输出非空 ENU/GCJ-02，
  地理质量保持 verified，仅 Lane/Link 与匹配质量为空；`RoadMapMatchingNode` 不得覆盖 heading、
  Movement 或任何世界坐标。SourceGeoRegistration v1 的 `coverage_enu_m` 同时兼容旧 Bundle 字段名。
- road9 沿用原表并增加 association/跟踪/地理/路网质量字段；默认查询返回像素降级轨迹，空间查询
  才要求至少两个有效 GCJ-02 点。Console2 完成数包含像素轨迹，BEV 只绘制有效地理轨迹。
- 回放器报告自然 EOF、候选帧/峰值、点列对齐失败、质量原因、遥测同步覆盖率与质量通过率、
  正式业务泄漏、Kafka/road9 精确对账和 MPS 性能。EOF 后顺序固定为 Kafka 排空、road9 追平、
  注销 Pipeline；每段对账后释放 loop-bound asyncpg 连接。
- `--show-in-web` 仅用于显式浏览器验收，默认批处理仍关闭 MJPEG，避免改变旧目录运行语义。

在 ADR-025 之前，`uav_track_complete_*` 为 0 是旧门禁结果：图像关联轨迹存在于
